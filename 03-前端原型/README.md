# 本间工作台 · 本机四步工作流

产品规范见[简易PRD](../01-产品需求/03-简易PRD-v0.1.md)，人工测试见[验收清单](../01-产品需求/06-当前验收清单.md)，开发验证和真实联调记录见[TASK.md](TASK.md)。当前状态更新于2026-09-20；M0–M5工程交付及本机预览更新完成，M6真实整本与用户内容验收、真人试玩仍待完成。历史小样结论不等于本次整本验收。

## 启动

Node.js 24、npm 11，首次`npm ci`，之后`npm run dev -- --port 3107`。生产预览用`npm run build -- --webpack`与`npm run start -- --port 3107`。只监听127.0.0.1，不对局域网公开。本机文件/OCR接口需要macOS的osascript、Swift、PDFKit、Vision和textutil；首次识别编译Swift，之后缓存复用。不需要安装PythonOCR包。

## 四步

1. 准备材料：真实上传到回环本机服务并读正文，必要时本机OCR；材料全部读取或由作者明确排除不可读项后，右下角「拆解大纲」。
2. 拆解与方向：模型返回带来源的大纲及2—5个改写方向，选方向、补充要求，右下角「生成蓝图」。
3. 创作蓝图：大纲、真相及九类节点的全部字段可修订；章节内搜索、每页30条记录，只编辑选中一条。字段与关联问题可定位，缺失引用不会自动清除。编辑自动保存为独立草稿，最多12份；预览正式提交后旧审查失效。最多20份蓝图历史，可查看对照、载入新草稿或逐份确认删除；满额时须先备份并整理，不静默丢旧版。
4. 交叉验证与导出：实际进度依次为设计门、全案生成、两路独审、两路互审、主模型复核；完整且无阻断问题才可「导出完整档案」。由服务端已通过快照生成ZIP，不接受浏览器自报通过或任意导出内容。打开保存位置由系统完成。

旧九阶段地址仍映射四步，旧项目记录不删。首页上传直接实际读文件后创建项目；读取取消不创建项目；最终跨LocalStorage/IndexedDB保存不是原子事务，失败保留项目ID和正文用于重试，避免重复创建。页面关闭会失去尚未保存的文件对象。

## 模型连接

蚂蚁平台连接、候选发现、固定小样测评、人民币测评账本与三模型自动分配已实现。2026-09-09最近任务记录显示真实测评9/9完成；不是今日重新测试或整本创作通过。正式创作通过OpenAI风格chat/completions发送`json_object`并在本地严格校验Schema，不假定提供商支持`json_schema`。

普通用户点击页面底部「配置模型」，服务器地址默认使用`https://maas-api.antdigital.com/v1`，只需粘贴API Key。保存仅记录平台连接，不外呼模型。之后的「读取候选模型」调用模型清单与公开人民币价格表，不生成内容；只有用户点击「开始受限测评」才生成小样。当前定向计划优先3模型×3任务（9题），唯一替补按已有预算和恢复规则参与，不遍历平台模型；历史4模型×3任务属于旧策略。合格完成后自动保存三个不同模型编号。受限配置文件为`runtime-data/studio-settings.json`（0600，目录0700，Git忽略），GET只返回安全字段和密钥存在标记，不返回密钥；换地址必须新填密钥。Key在粘贴及POST提交时会短暂存在页面内存和本机请求中，但不进入浏览器持久存储。

测评使用独立的`runtime-data/model-evaluation.sqlite`人民币账本：请求前原子预留，内部计划不超过800分，单次公开价估算增加20%安全余量，全部预算状态不超过1000分；价格读取10分钟后失效，未知或复杂价格不运行。平台完全不返回Token用量但正文完整时按字节上界和最高预留保守核算；部分、非法或超过预留的用量会停止。正文分片只采用明确的最终文本，不把推理内容当答案。当前按模型预留输出空间：DeepSeek Pro 16384 Token、Kimi 8192 Token并使用low推理档、其他4096 Token，最长等待240秒；`length`表示回答被截断，旧版900 Token记录保留为历史；评分契约已修订为juben-model-eval/1.1，旧分数不能混入新测评。真正的空正文、选项异常等响应会结算已知费用、自动跳过候选并在既定轮次和研究候选范围内免费复核价格后补入替补；模型身份或用量无法核实时仍立即停止。费用结算、题目视图、候选排除和续测资格使用SQLite原子提交及跨进程版本校验。该账本不能保证平台最终结算绝对不超过10元，真实运行前应同时设置蚂蚁账号侧限额。**该测评账本不覆盖正式拆解、蓝图或全文审查；正式创作使用下方独立项目预算。**测评输入是内置固定小样，不发送用户剧本。模型得分记录结构、证据、原创、格式、延迟、Token和按公开价格计算的费用；它只用于初始分工。已有运行记录后可查看或下载本机确定性生成的Markdown测评报告；中断报告明确缺项和待核对费用，不调用模型。

LiteLLM方案位于`infra/litellm`，固定已发布版本，不复制`litellm-litellm_internal_staging`源码。自动分配后会在Git忽略的runtime-data生成三个无密钥别名配置，并关闭LiteLLM自身的隐藏重试，避免绕过工作台的人民币账本和候选排除记录。评分、截断识别和自动换候选由工作台负责；LiteLLM负责后续统一接口。本批尚未自动启动代理，正式工作流暂时使用蚂蚁官方兼容接口；代理启动、健康检查和进程恢复安排在本机MVP后续批次。

也可使用本机`.env.local`（Git忽略）或进程环境设置；环境变量整组优先，存在时页面只读，避免两个来源混用密钥：

- `STUDIO_API_BASE_URL`：兼容接口基础地址（例如本机LiteLLM的/v1）
- `STUDIO_API_KEY`：仅服务端读取
- `STUDIO_MAIN_MODEL`：主模型编号
- `STUDIO_REVIEW_A_MODEL`、`STUDIO_REVIEW_B_MODEL`：两个不同审查编号，三者不可相同

页面保存的配置供新的费用预览及后续任务使用；确认前若配置变化，原预览失效，需重新预览。运行中的任务使用启动时冻结的配置；修改进程环境或`.env.local`后需在无运行任务时重启。配置存在不表示已实测可用。输入正文会发往你配置的服务，须先明确服务、模型与费用，不能把真实密钥提交仓库。未配置返回503且零外呼，前端主要AI按钮不可用。

Skill工作流以juben-design/1.0约束嵌入服务端编排提示，未声称模型实际执行本机Skill工具。正文指令视为数据；证据可回查、全链通过和玩家/主持隔离均作为门槛；模型判断仍可能有误，不能替代真人试玩。

## 存储与恢复

新正文/创作内容通过独立Service存IndexedDB，CAS revision防覆盖；旧项目metadata在LocalStorage。输出目录本机注册ID→路径写入`runtime-data/directories.json`，目录0700、文件0600，对前端只返回名称/opaque ID。Git忽略runtime-data、上传、构建产物和密钥。实际原文件不修改。

模型任务先在浏览器保存请求UUID，服务端在受限`runtime-data/studio-jobs.sqlite`登记请求指纹、进度与结果，再外呼；同UUID跨实例恢复不重复调用。任务结果、通过快照及成功分段/合并摘要保留7天，内存另有2小时缓存；服务进程退出或5分钟未更新的运行任务会标记中断，不自动重跑。404或中断不代表此前零费用。手动重试相同材料可复用匹配模型/参数/要求/内容的成功摘要。当前没有账号系统、长期项目数据库、持久执行队列或云备份；SQLite任务存储不等于这些能力。

导出为含Markdown正文/蓝图JSON/审查报告的ZIP，按角色及主持分区；现不提供Word/PDF转换或真人试玩录入。目录仅在点击导出后写入，排他创建新文件避免覆盖已有档案。

## 处理限制

每批最多2000份材料；单文件25MB、单正文300000字符、PDF60页、图像4000万像素。拆解入口允许12,000,000字节JSON正文及2000份材料；超过20000字节自动无损切段（每片20000字节以内、合批30000字节以内、最多512批），每组最多4份摘要按完整载荷预算逐层合并，保留可核对原文引用。所有批次成功才形成最终拆解，覆盖统计不代表语义绝无遗漏。

每次模型调用的数据载荷仍限600000字节（包括该步中间报告；系统提示/Schema另附），单回复2MB，每调用240秒。正文已分角色/轮次/模块逐份生成，蓝图仍需适配单次上下文。正文快照超过350000字节时进入分段审查：每段和关联范围执行两路独审、互审和主模型复核；请求附完整蓝图，原文按48000字节切分，为中间报告预留200000字节。完整请求无法容纳则保留正文并拒绝，不截断。最多2个并发创作任务，内存最多24份记录（终态缓存2小时），SQLite终态保留7天。此前成功调用可能已收费。音视频转写和压缩解包尚未实现。

## 完整项目备份与恢复

在项目标题旁选择“备份项目”，查看内容数量后下载JSON；在“我的项目”选择“从备份恢复”，核对预览后恢复为新副本。保留原项目、材料正文/排除状态、拆解与要求、方向、正式蓝图、最多20份历史、12份独立草稿以及正文和审查报告。包含分段报告的新备份使用v4，其他新备份使用v3；继续读取v1–v3旧备份。保留阶段、模块及分段成果并剥离任务/执行编号，所有运行态转为中断。备份上限64 MiB，超限拒绝，不截断。仅备份已保存内容，本页蓝图草稿先尝试落盘，失败不提供下载；正在运行或等待确认的任务须先处理完毕。

恢复后使用新项目编号，目录权限和预算需重新设置，不接续旧任务。导入文件的审查结论只作为可查看的历史，不能获得本机导出资格；必须重新审查。完整备份不包括磁盘原始文件、服务端费用账本、配置、任务缓存、通过凭证或浏览器目录句柄，这些内容需分别保管。

恢复在浏览器跨页锁下写入正文和恢复记录，再发布项目索引；索引失败补偿，刷新列表核对未完成记录。同一次操作重试不会重复建副本，仍有记录的操作不能换用另一份备份；已经全部回滚且无持久记录的失败尝试不永久占用操作编号。不支持跨页锁的浏览器拒绝恢复。旧“项目索引排错”下载只含索引，不是完整备份。

## 蓝图草稿

“草稿已在本机保存”表示已写入浏览器IndexedDB，尚未替换正式蓝图。刷新或离开后，可在“查看已保存草稿”中对照恢复，恢复会创建新草稿并保留旧份。原基准过期时不能直接覆盖；须明确对照后以当前版本继续编辑，再预览正式提交。

保存失败会保留输入并提供重试或“另存为新草稿”；站内切换步骤/项目后回来仍保留未落盘输入，关闭或刷新页面前会提示。只有显示已在本机保存的内容才具备刷新恢复保障；浏览器关闭警告不能抵抗强制退出、系统崩溃或清除站点数据。最多12份草稿，需要作者逐份确认删除，不自动清理。完整项目备份与新副本恢复见[备份与恢复说明](#完整项目备份与恢复)。

## 蓝图结构与历史

角色、关系、事件、信息发放、推理结论、线索、轮次、主持触发和终局均可新增、逐项编辑和确认移除；记录编号保持固定。移除前显示受影响关联，其他记录仍保留原引用，作者须明确修复；删除线索限定角色不会自动把私人线索变成公共线索。当前章节可撤销最后一次移除，切换章节、定位问题、结束本页草稿或刷新后撤销入口失效。跨页正式更新不清掉仍活跃的本页撤销记录。

静态检查只覆盖字段和关联，支持按章节/记录定位，不代表语义审查或真人试玩。未填写完整也可以保存草稿；提醒不会阻断后续生成。第四步可展开已保存正文和六阶段报告，查看阻断、提醒、引用及检查结论；未完成和旧蓝图成果明确区分。当前没有把自由文本自动映射为精确字段的能力。

历史记录只含版本号与蓝图内容，不补造时间、标签或来源。对照后可载入为当前项目的新草稿，正式提交时生成更大版本号，不恢复旧通过凭证。整理历史使用独立版本校验，不改变正式修订或草稿基准，所以历史满额时可以删除一份不再需要的旧版后继续提交原草稿。对照到首次写入期间另页变化也会拒绝恢复；失败重试与另存不能绕过该检查。删除历史不能撤销，请先使用完整项目备份。

## 正式创作预算

每个项目先打开「创作预算」填写累计额度，再由四步操作进入费用预览，点击「按项目额度开始」才发起模型调用。额度不预填，不沿用测评10元或历史小样3元。预算可修改，跨页面冲突保留输入；提高额度、换步骤和手动重试都不清除费用。

账本与任务共用受限`runtime-data/studio-jobs.sqlite`，记录逐次报价、预留、发送、用量核算及待核对费用。预算准入与任务登记原子提交；永久任务编号与费用记录不随7天结果清理而删除。费用预览绑定项目、当前资料、模型连接及预算版本，10分钟内单次使用。每次请求按包含系统提示、Schema和输出上限的完整载荷原子预留；预览给出调用规模和保守估算，实际按每次请求结算。

目前只支持精确核对蚂蚁官方公开的人民币平价报价，不替换当前模型，不使用复杂价格或未知价格。报价有效10分钟，过期只免费刷新价格；涨价后按新价核对剩余预算，失败不沿用旧价。正文截断、坏JSON等失败仍记录已知用量；超时、模型身份/用量不明或超出预留时保留费用并停止后续调用。界面提供逐次记录和显式账单核对，填写金额及依据后才能解除待核对状态。

费用按报价与用量向上取整到分，属于工作台核算，供应商账单为最终依据。预算保护不保证供应商最终扣款绝不超额；本轮开发仅验证假供应商与故障场景，尚未用真实整本核对账单。费用数据库不进入GitHub或浏览器项目备份，不要随意删除它来重置预算。

`npm run typecheck`、`npm run lint`、`npm run test`、`npm run build -- --webpack`、`npm run test:e2e`。先构建再运行E2E，不同时重建其服务；E2E使用3108端口，用户验收使用3107。

原五步Mock的历史86条界面场景保存在tests/legacy-e2e，已不适用四步UI，不计作当前通过；底层旧单元仍运行。当前E2E实际TXT读取与浏览器存储真实执行；模型/系统选择窗口采用边界fixture，不外呼、不自动选择用户目录。PDF/图片/RTF读取另有真实本机组件单元验证。

## 首页拖拽与换本

首页整块拖拽区替代说明卡和最近项目表，已有项目仍在侧栏/项目列表。支持目录递归和读取全部批次，保留相对路径，滤掉系统文件。目录API遵循[浏览器目录读取说明](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemDirectoryReader/readEntries)，每次读到空批次才结束，避免遗漏超过100个条目。深度/数量保护会整批拒绝，不默默漏文件。

项目已有输入时按钮为“更改文件夹”。读取完新批次才CAS替换；任何error或没有成功正文会拒绝替换，unsupported项可登记但需处理/排除才能分析。取消读取或存储失败保留旧批次。进入保存阶段按钮禁用取消，避免误报。替换仅影响当前输入与关联有效性，不改项目名、输出位置或原文件。旧蓝图和审查保留但过期。

## 拆解超时诊断与真实验证

拆解分段门槛独立于600KB请求安全上限：超过20KB输入使用20KB以内片段、30KB以内合批。单份摘要上限2500字、4条短引用，提示建议4条待定项、结构校验允许最多8条；合并按包含创作要求的完整载荷组包，每次拆解载荷不超过128000字节（系统提示/Schema另附）。较小批次增加请求数量，不承诺供应商必在240秒内返回；每批成功后保留摘要，失败停止后续请求。超过门槛的输入即使不足600KB也分段。成功缓存绑定策略版本，策略变化不错误复用旧分段。

拆解任务保存最近一次调用的模型编号、阶段、输入字节、输出上限、开始时间、耗时和错误码，不保存Key或原始请求。旧记录缺少这些字段时不补造。材料已就绪时，失败页说明材料保留并提供手动重试，刷新不会重新发起调用。

真实接口校验独立于普通回归：`npx vitest run --config vitest.live.config.ts`默认跳过，正常单元/E2E不会运行它。仅在明确授权后设置`STUDIO_LIVE_VERIFY=1`运行；使用当前蚂蚁主模型和自有合成10文件样例，最多3次请求。逐次按新鲜公开价格、请求字节上界、最大输出及20%余量预留，累计不超过300分；这是保守估算保护，不能替代供应商最终账单。首次失败停止，不自动换模型或重试。

手工验证报告写入运行位置的受限`runtime-data/verification/analysis-live.json`，含调用规模和保守预留，不含正文或密钥；存在同名报告则拒绝重跑。建议在隔离副本执行，通过`STUDIO_LIVE_SETTINGS_ROOT`指定现有受限配置目录，避免写入用户任务库。报告真实通过也只证明该合成样例，不能代替用户整本验收。当前真实验证状态以TASK为准。

## 项目删除与分段引用

项目列表与侧栏名称后提供垃圾桶，轻微悬停动效遵守减少动态效果偏好。确认后删除此浏览器项目索引及四步创作内容，不删除原文件、输出档案或服务端任务历史；运行中或提交状态不确定时拒绝删除。IndexedDB事务先冻结写入，索引失败恢复正文，完成后无正文墓碑阻止旧标签页复活。删除确认不能替代完整创作数据备份。

长材料拆解不再要求模型逐字复写文件UUID、摘录或位置。程序将完整原文拆成至多160个UTF-16字符的编号片段（不切代理对），模型只选择本次可用编号；程序回填真实摘录及字符位置。分段、合并、最终汇总均验证本次局部编号集合，未知编号直接拒绝，不作模糊匹配或自动换引用。编号元数据计入30KB合批和128KB完整载荷预算，缓存策略升级为source-analysis/3-citation-selection。纯空白批次由程序核对、不调用模型，覆盖说明明确包含这类批次。此机制保证摘录来自原文，不证明摘要事实推断或引用关联一定正确。

本轮限定长材料分段链路；20KB以内的直接分析仍使用原有引用契约。真实整本未联调，旧失败记录不会因更新代码自动变为成功，也不会自动付费重试。

## 本机长任务与休眠恢复

当前本机版本在每个创作任务开始时建立并核实 macOS 防空闲休眠保护，结束或失败后释放；保护建立失败则不调用模型。仅任务存续期间有效，不永久修改电源设置，也不阻止手动休眠或合盖。当前保护实现仅支持 macOS，其他系统会明确拒绝开始，移植时需提供对应实现。

执行监测每秒检查，超过15秒的回调间隔或系统时钟明显回退会停止在途请求，记录 HOST_EXECUTION_PAUSED；该诊断涵盖休眠、进程暂停和系统时钟变化，不直接归因于模型供应商。正常执行下达到240秒仍报 MODEL_TIMEOUT。后台每10秒续租，跨进程恢复采用租约快照条件更新，避免误中断已续租任务。释放保护异常仅记录静态错误码与任务编号到服务日志，不暴露原文或凭证。

恢复后不会自动发起模型调用；手动继续复用匹配版本、材料及配置的成功拆解摘要。此次电源修复未改变拆解缓存策略；已完成批次无需为本修复重算。迟到结果不能覆盖中断终态。当时的电源修复仅验证拆解；正文/审查的逐阶段恢复现由M4a提供，模块化正文由M4b提供，全覆盖分段审查由M4c提供；真实作品仍待验收。

2026-09-10受控真实验证已通过：当前DeepSeek主模型处理自有10文件样例，2次分段读取+1次汇总，319秒，全部文件覆盖及引用契约校验通过。累计保守预留1.10元，非供应商实际结算金额。此结果不替代用户原整本内容验收，也不代表正文/审查全流程已验证。

### M4a/M4b · 模块正文与审查的阶段保存

当前七个大阶段按生成/审查单元逐项保存完整响应，两个审查模型并行时一路失败仍保留另一路。第四步可查阅部分正文、六阶段报告、原文依据及未完成项。中断后刷新只查询；选择“查看继续费用”并确认后，按相同项目、蓝图、模型配置及协议复用已保存阶段。配置不兼容时预览明确从头执行；需要保留旧成果时先下载完整备份。

首次费用预览按G+6次保守估算（G为正文份数，短篇主模型G+2次、两路审查各2次，本地聚合不收费）。长篇首次生成后保存计划并停止，再次预览确认后才执行分段审查；分段预览按G+1+5S次计价（S为正文段及去重关联范围之和），绑定冻结计划摘要，旧预览不能授权新增调用。复用会减少实际调用，不是剩余费用的精确报价。未知费用先核对；已收费但未保存项可能再次收费。无效引用/来源响应保留但不可复用；有效阻断需修订蓝图后重审。成功检查点和费用不随七天任务清理删除，存于受限SQLite，不进入GitHub。

正文按角色/轮次/模块生成：角色本和私人信息各每角色一份，每角色每轮一份更新，每轮公共材料一份，主持开场一份、每轮主持手册一份，每个终局一份；最多240份。每份单独校验目标与来源并落盘，继续只补未保存项；正文每页30份、展开后加载。私人线索仅允许指定角色和轮次，公共线索不得提前发放。来源关联不代表已自动获知。开始前检查全部目标载荷及来源条数。长篇每段和同角色/同轮次/共同来源的相邻关联均直接进入五路审查，核对hash、精确范围和原文摘录；任何早期阻断不能被最终通过抹除，缺报告不能导出。相邻关联不证明任意非相邻段语义一致，仍需人工核对与真人试玩。

### 分段审查交付边界

每份分段报告限40000 UTF-8字节。超限或覆盖/引用契约不符时，保留未采用响应供查看并停止；有效阻断仍保留，需要改蓝图后重审。开始分段调用前，按全部报告最坏体积、真实正文、蓝图、完整清单、文件名及ZIP开销核对64 MiB上限，不能完整交付时拒绝追加分段调用并保留正文。ZIP主持目录包含全部原始报告与覆盖清单，采用紧凑JSON，不删字段。
