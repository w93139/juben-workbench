# 前端原型开发区

这里是后续前端代码的唯一开发位置。

在开始编码前，先使用 ../01-产品需求/01-VS-Code需求理解提示词.md 完成需求理解和技术方案。演示数据从 ../02-演示与测试资料 中按需复制，不要直接修改参考资料。

## 运行

当前环境：Node.js 24、npm 11。首次使用运行 `npm ci`，之后在本目录运行：

```sh
npm run dev
```

打开终端给出的本地地址，默认 http://127.0.0.1:3000。应用无需环境变量、原参考目录、外部模型或数据库。

## 阶段 A 已有能力

- 首页、可搜索筛选的项目列表、空项目和演示副本创建。
- 原始《名字之外》只读，副本独立保存项目名称、创作备注和决定状态。
- 九个创作阶段导航与档案摘要；蓝图支持人物、关系、时间线、谁知道什么、线索与结论、轮次的只读浏览。
- 历史检查标注来源与适用版本；材料准备百分比不表示体验通过，真人试玩保持“尚未真人试玩”。
- 自动保存、刷新恢复、过期修改拦截、存储失败报错、损坏数据备份与确认恢复。
- 桌面及窄屏布局，键盘可操作的表单和弹窗。

当前可以编辑项目资料、决定记录和参考研究操作，剧本底稿尚保持只读。真实OCR与AI调用不在本轮原型范围；蓝图编辑、正文生成、审查修复、试玩录入、受众预览及导出按C—E批次实现。作者工作区含谜底，不能当作玩家端使用。

### 找到决定状态和检查记录

打开自己的项目，在项目标题下点击“修改决定状态”，然后在某条决定的“修改状态”下拉框中选择“暂定”；看到“决定状态已保存”即可关闭弹窗。同一排的“检查与试玩”可直接查看检查记录，不受窗口宽度影响。在任何创作阶段也能使用这两个入口。

项目总览和9个阶段的标题与常用按钮固定在顶部。浏览下方具体功能时，仅下方内容滚动；也可把焦点移到“具体功能内容”区域后用PageDown滚动。每个阶段顶部有对应的“下一步”，最后一步返回项目总览。切换页面不会标记阶段完成，原有校对等操作条件仍生效。

如果顶部显示的是“查看创作决定”，说明当前是只读原始样例；先点击“创建演示副本”，再在副本里修改。“编辑项目”用于名称和备注。

## 阶段 B：参考研究与原创方向

刷新 http://127.0.0.1:3107 后，打开项目总览，在项目标题下方点击“继续参考研究”。已经在材料中心时，顶部按钮显示“下一步：参考本拆解”，进入拆解页；仍需完成校对和阅读范围确认才能开始模拟拆解。

- 自己创建的项目：直接进入材料中心，保留原来的研究进度。
- 原始只读样例：先进入副本创建，填写名称并点击“创建并进入材料中心”。原始样例不会被修改。
- 在材料中心，点击“载入研究练习包”；若显示“练习包已载入”，说明已添加，按旁边提示继续模拟OCR或校对。

接着依次操作：

1. 载入研究练习包，开始模拟OCR；可勾选一次失败演示，失败后重试。运行中可取消；刷新后会继续模拟进度。
2. 保存两处文字校对、排除重复页、记录缺失材料。处理完四项后确认阅读范围。
3. 开始模拟拆解，查看来源、分析与待确定事项；完整原作真相、时间线和人物关系因材料不足而保持未知。
4. 在机制卡片保存“保留／改造／舍弃”和理由，再继续原创方向。
5. 保存人数、题材、时长、总计100%的体验比例、禁止内容和创意。目标变化会显示迁移风险，原5人样例不会被自动改写。

这份练习包使用既有参考机制研究的8条记录，其中3份摘录用于校对练习；OCR异常和练习页码是人工设置的演示数据，原始扫描页没有导入。研究数据在 `src/mocks/research.json`，保留记录定位及来源SHA-256。材料里的命令句仅作为研究数据。

### 文件和文件夹导入

“选择本机文件”支持多选；“选择文件夹”包含子目录。选好后自动开始整理与模拟上传，进度经过整理、模拟传输、保存清单，真正保存成功才显示100%和结果，无需点击登记或确认完成。文件内容不上传，进度不是实际网络字节进度。无效和疑似重复项自动略过；可展开本批清单搜索、分页查看原因。支持取消；保存失败在当前页保留清单，点击“重试导入”重新读取最新材料并检查重复项。离开或刷新会取消未完成的导入，需要重新选择；已保存材料保留。

- 当前单批2000份、单项目5000份；这是前端原型保护，不是后端OCR服务上限。策略统一位于 `src/domain/source-import.ts`。
- 本地登记取消单文件30MB硬限制，保留大小信息。超过100MB的文档/图片/压缩包、超过2GB的音视频会提示未来分段/分页/分片上传；不阻止登记。
- 按扩展名分类图片、PDF、办公文档、文本、音频、视频、字幕和压缩包。音频等待语音转写；视频等待语音转写或画面文字识别；字幕保留时间位置；压缩包仅登记待解包。没有真正转写、解码、抽帧、解压或读正文。
- 空文件、系统/隐藏文件、不支持格式和疑似重复在预览中列明原因，用户可以登记其余有效项。不同子目录的同名文件分别保留。疑似重复以相对路径、大小、可用修改时间判断，没有比对文件内容，不等于内容相同认证。
- 材料清单支持搜索、格式筛选，每页30份。只保存名称、大小、类型、目录内相对路径和修改时间；原文件不上传、不复制到存储。元信息太多仍可能填满浏览器存储，此时旧数据不覆盖，待导入清单在当前页保留。数量超过项目剩余容量时本批不保存，提示分批选择或另建项目。

文件夹选择使用浏览器原生能力；不支持时提示改用文件多选。技术依据：[MDN目录选择](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory)及[相对路径](https://developer.mozilla.org/en-US/docs/Web/API/File/webkitRelativePath)。文件格式能登记不意味着已经验证可解码；实际服务接入时再探测格式、页数、时长和成本。

识别问题、范围确认、机制取舍和方向点击保存后写入本机。材料或校对变化后，旧范围、拆解和方向失效，之前的取舍和方向草稿保留；修改范围说明需要重新拆解。任务进度只在项目页面打开时推进，不模拟后台服务。

### 输出储存位置

从“参考本拆解”起，后续每个阶段内容上方都有“输出储存位置”。点击“选择文件夹”，在系统窗口中选择桌面或其他位置的文件夹，再填写本阶段子目录并点击“保存输出路径”；也可手动填写完整本机路径，例如 `/Users/你的用户名/Desktop/剧本输出` 或 `D:\剧本输出`。选择后显示“所选文件夹：名称”，不会从名称猜测绝对路径。总目录在各阶段共用，子目录分别保存；刷新保留，不同项目隔离。留空总目录且未选择文件夹表示尚未设置本机输出位置。原始样例只读。

当前只保存计划位置。用户点击后调用系统目录选择器，请求只读访问以取得目录引用，不枚举目录、不读取正文、不创建目录或写出文件；内容仍保存在浏览器项目中。拆解任务记录启动时已保存的路径，修改设置不改变当前/旧任务的路径记录；下一次开始或重试拆解采用新设置。旧任务未记录路径时如实说明。路径表单保存失败保留输入，跨页修改须明确载入最新状态后才能覆盖这一项。

`src/domain/output-settings.ts` 集中管理默认子目录、输入校验及路径拼接；Service保存项目设置与任务路径快照。格式3新增可缺省的设置，旧项目读取补默认值但不写存储，下一次成功修改时才保存；既有任务缺少路径字段保持可读。

目录适配器位于 `src/services/browser-output-directories.ts`。系统目录选择器请求 `startIn: desktop`、`mode: read`，起始位置最终由浏览器决定。不支持时明确提示手动输入，取消或拒绝访问不改变原设置。LocalStorage仅保存目录引用编号/名称；真正的浏览器目录引用单独存于IndexedDB `juben-workbench:output-directories:v1`。保存项目前验证引用仍存在；引用丢失时可重新选择或改手动路径。原型不申请写权限，未来实际输出仍需核对授权。每次选择有独立编号，不能把同名目录当成同一个位置。

选择仅更新当前草稿，点击保存才更新项目；选中后放弃的目录引用可能仍留在本浏览器引用库，但不关联项目、不产生文件。引用不能跨浏览器设备迁移。技术依据：[MDN目录选择](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)、[目录名称](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemHandle/name)。

## 数据与结构

```text
src/app          页面路由与布局
src/components   工作台、项目表单与 UI 组件
src/domain       数据类型、校验与中文展示规则
src/services     ProjectService、Mock 实现、浏览器存储适配器
src/mocks        独立 JSON 快照及只读 Markdown 副本
tests            Service 测试与浏览器场景测试
```

业务组件通过 Service 接口获取数据。`MockProjectService` 合并只读样例与本机项目；未来可替换为真实 API 实现。TanStack Query 管理加载与缓存，Zod 校验输入及持久数据。UI 使用 Tailwind CSS 与 shadcn/Radix 组件。

LocalStorage 只写 `juben-workbench:projects:v1`，当前内容格式为 `schemaVersion: 3`，包含项目版本号、名称／备注、决定状态和参考研究状态。兼容旧格式1和2：读取时保留原存储不变，首次成功修改才写为格式3；失败不会覆盖旧数据。物理存储键和预览地址保持不变。决定状态即改即存，项目资料点击“保存修改”后写入本机。数据限定在同一浏览器、同一地址（协议、域名和端口）；没有跨设备同步，清除网站数据会丢失本机项目。多标签页使用浏览器 Web Locks 串行写入和版本号检查；不支持 Web Locks 的旧浏览器只保证同页面串行操作，不提供跨标签页原子保证。

样例按项目状态及原始结构数据导入，保留来源路径与 SHA-256。历史静态检查 134/134 来自既有结果，应用不会重新运行它。JSON 包含资料展示需要的摘要，Markdown 副本可直接阅读；运行时不读取受保护的原目录。

只有需要更新演示快照时，才在保有相邻参考目录的环境运行 `python3 scripts/import-demo.py`。脚本只读取参考资料、写入本应用 `src/mocks`。

## 验证

```sh
npm run typecheck
npm run lint
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
```

浏览器测试会在 3108 端口启动生产构建，每个测试使用隔离的浏览器存储。测试前需完成构建，不占用或清空个人浏览器数据。截图与失败追踪写入忽略目录 `test-results`。

目录选择场景使用完整Chromium和每测试独立的临时profile，测试后关闭并删除；本机打包Chromium的无痕上下文在读取OPFS目录引用时会退出，纯API最小复现相同。此fixture保留真实目录引用与IndexedDB往返，仅替代系统目录选择器返回值；不假称已操作用户电脑上的原生窗口。完整浏览器模式依据[Playwright文档](https://playwright.dev/docs/browsers)。

工具链暂用 ESLint 9.39.5，匹配 Next.js 配套的 React / import / 可访问性插件 peer 约束。npm 会提示该大版本维护状态；后续插件支持 ESLint 10 时一并升级。当前依赖审计无已知漏洞。
