# 前端原型开发区

本目录是应用代码的开发位置。产品规范见[简易PRD v0.2](../01-产品需求/03-简易PRD-v0.1.md)，当前用户操作见[验收清单](../01-产品需求/06-当前验收清单.md)，本轮任务和开发验证见 `TASK.md`。

当前仍是Mock。A已由用户验收，B已有材料与参考研究能力；本轮将九个创作阶段合并为五步，保留原有数据与能力。C蓝图编辑、D生成审查、E试玩导出主体仍待开发，相关页面只读档案不能算作完整交互。

## 运行

使用Node.js 24、npm 11，首次运行 `npm ci`，之后在本目录运行：

```sh
npm run dev
```

打开终端给出的地址，默认 http://127.0.0.1:3000 。用户既有预览地址是 http://127.0.0.1:3107 ；需要继续使用该地址下的浏览器项目时，先停掉占用进程，再运行 `npm run dev -- --port 3107`。地址不同会使用不同浏览器存储。

运行无需环境变量、参考原目录、模型账号或数据库。演示快照已包含在 `src/mocks` 中；原资料与Skill只读，普通开发不重建快照。

## 五步工作台

| 页面 | 对应原有阶段 | 默认地址后缀 |
|---|---|---|
| 准备材料 | materials | materials |
| 确定创作方案 | analysis、mechanisms、direction | analysis |
| 设计故事 | blueprint | blueprint |
| 生成与检查 | generation、review | generation |
| 试玩与导出 | playtest、export | export |

旧九阶段地址仍可访问，同组显示同一个组合页面。底层阶段标识、数据及默认输出子目录保留，不迁移或清空项目。首页、项目列表、新建项目和项目总览独立；编辑可直接进入故事或检查，不强制按序浏览。

顶部固定当前页面、一个主操作、修改决定和一个检查入口，只有下方“具体功能内容”滚动；键盘可将焦点移入后用PageDown浏览。主操作按进度指向当前任务或下一主步骤，导航不标记完成、不绕过校对等条件。取消每页“继续参考研究”和右侧重复检查，长说明、来源与分析按需展开；重大缺口、Mock、历史与未试玩状态仍可见。

原始《名字之外》只读，先创建演示副本再修改。在顶部“修改决定状态”中可将决定改为暂定并保存；只读样例显示“查看创作决定”。项目名称和备注独立编辑。检查入口展示历史来源与版本，“AI／静态通过”和“尚未真人试玩”不会混成一个完成状态。

## B阶段：准备材料与确定创作方案

1. 在自己的项目进入“准备材料”，选择本机材料或载入研究练习包。原始样例需先创建副本；已载入练习包不重复添加。
2. 练习包可模拟OCR、演示失败后重试、取消或刷新续进度。保存两处文字校对、排除重复页、记录缺失材料，再确认阅读范围。
3. 进入“确定创作方案”模拟拆解。推荐玩法、风险和原创方向在同一页，参考分析与来源可展开。完整原作真相、时间线和关系因材料不足保持未知。
4. 人数、题材、时长、禁止内容和创意允许先存方向草稿，不要求先完成研究。体验先选偏推理、偏情感、偏互动或均衡，展开后可精调总计100%的比例。
5. 调整推荐机制的保留／改造／舍弃与建议理由，集中保存或确认。推荐默认为暂定；最终确认同时保存机制和方向，并核对研究条件，不能部分确认或把草稿当作已确定。

第二步可直接填写创意，再回第一步处理材料；进入第三步不表示样例已按新方向改写。材料或校对变化会使旧范围、拆解与方案确认失效，已有机制选择和方向草稿保留，待核对后重新确认。

研究练习包使用既有8条机制研究记录，3份摘录用于4项校对练习；异常与练习页码是人工设置，未导入原始扫描页。`src/mocks/research.json` 保留记录位置和来源SHA-256。用户文件仅登记元信息，不能伪造其分析结果；材料里的命令句只作为数据。

### 文件和文件夹导入

“选择本机文件”支持多选；“选择文件夹”包含子目录。选好后自动开始整理与模拟上传，进度经过整理、模拟传输、保存清单，真正保存成功才显示100%和结果，无需点击登记或确认完成。文件内容不上传，进度不是实际网络字节进度。无效和疑似重复项自动略过；可展开本批清单搜索、分页查看原因。支持取消；保存失败在当前页保留清单，点击“重试导入”重新读取最新材料并检查重复项。离开或刷新会取消未完成的导入，需要重新选择；已保存材料保留。

- 当前单批2000份、单项目5000份；这是前端原型保护，不是后端OCR服务上限。策略统一位于 `src/domain/source-import.ts`。
- 本地登记取消单文件30MB硬限制，保留大小信息。超过100MB的文档/图片/压缩包、超过2GB的音视频会提示未来分段/分页/分片上传；不阻止登记。
- 按扩展名分类图片、PDF、办公文档、文本、音频、视频、字幕和压缩包。音频等待语音转写；视频等待语音转写或画面文字识别；字幕保留时间位置；压缩包仅登记待解包。没有真正转写、解码、抽帧、解压或读正文。
- 空文件、系统/隐藏文件、不支持格式和疑似重复在预览中列明原因，用户可以登记其余有效项。不同子目录的同名文件分别保留。疑似重复以相对路径、大小、可用修改时间判断，没有比对文件内容，不等于内容相同认证。
- 材料清单支持搜索、格式筛选，每页30份。只保存名称、大小、类型、目录内相对路径和修改时间；原文件不上传、不复制到存储。元信息太多仍可能填满浏览器存储，此时旧数据不覆盖，待导入清单在当前页保留。数量超过项目剩余容量时本批不保存，提示分批选择或另建项目。

文件夹选择使用浏览器原生能力；不支持时提示改用文件多选。技术依据：[MDN目录选择](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory)及[相对路径](https://developer.mozilla.org/en-US/docs/Web/API/File/webkitRelativePath)。文件格式能登记不意味着已经验证可解码；实际服务接入时再探测格式、页数、时长和成本。

识别问题、范围确认、机制取舍和方向点击保存后写入本机。材料或校对变化后，旧范围、拆解和方向失效，之前的取舍和方向草稿保留；修改范围说明需要重新拆解。任务进度只在项目页面打开时推进，不模拟后台服务。

### 输出储存位置

项目共用一个总输出目录。各页默认只显示计划位置和“更改输出位置”，展开后可选择文件夹或手动填写完整路径；默认子目录自动沿用，高级设置保留原有八个输出阶段的单独覆盖。保存后刷新仍在，不同项目隔离，原始样例不可修改。

系统选择器请求从桌面打开，最终起始位置由浏览器决定。所选目录只显示名称，不猜测绝对路径；手动路径和目录引用互斥。取消、拒绝或不支持时保留原输入，不支持可手填。目录选择只改草稿，点击保存才更新项目。

当前只保存计划位置，不列举目录、不读正文、不申请写权限、不创建目录或写出文件。拆解任务记录启动时已保存的位置，后续路径变化不改运行中或旧任务；旧任务未记录时如实显示。路径设置不改变材料版本或验证结论。

`src/domain/output-settings.ts` 管理默认子目录、输入校验和组合路径；Service保存设置及任务快照。`src/services/browser-output-directories.ts` 调用 `showDirectoryPicker({ startIn: "desktop", mode: "read" })`，LocalStorage保存引用编号／名称，实际引用单独存在IndexedDB `juben-workbench:output-directories:v1`。同名目录仍用独立编号；保存前核对引用存在，丢失时引导重选或手填。

目录引用不能跨浏览器迁移。放弃保存后，未关联项目的引用可能仍留在浏览器库中，不产生文件。真实输出时还要检查目录及写权限。保存失败保留草稿，跨页冲突需先明确载入最新状态，再决定是否保存。技术依据：[MDN目录选择](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)、[目录名称](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemHandle/name)。

## C—E后续能力

- 设计故事：C实现人物、关系、事件、知识、证据链、轮次与终局的结构化编辑和版本。现有统计与内容是只读档案。
- 生成与检查：D实现分模块模拟生成、候选版本、双模型独立检查、分歧处理和复查。蓝图完成后与正文生成后各检查一次，入口合并不改变时机；历史检查不当作本次执行。
- 试玩与导出：E实现先导出标明未试玩的试玩包，再录入真人反馈、修订并导出新版；玩家材料与主持谜底分开。当前不提供虚假的导出成功状态。

作者工作区含谜底，不能当作玩家端或生产权限保障。真实OCR、AI与输出在F后端计划中实施，LiteLLM接入安排见[评估](../01-产品需求/04-多模型审查与LiteLLM评估.md)及[后端计划](../01-产品需求/05-后端开发计划.md)。

## 数据与结构

```text
src/app          页面路由与布局
src/components   工作台、项目表单与 UI 组件
src/domain       数据类型、校验与中文展示规则
src/services     ProjectService、Mock 实现、浏览器存储适配器
src/mocks        独立 JSON 快照及只读 Markdown 副本
tests            Service 测试与浏览器场景测试
```

业务组件通过 Service 接口获取数据。`MockProjectService` 合并只读样例与本机项目；未来可替换为真实 API 实现。TanStack Query 管理加载与缓存，Zod 校验输入及持久数据。UI 使用 Tailwind CSS 与 shadcn/Radix 组件。

LocalStorage 只写 `juben-workbench:projects:v1`，当前内容格式为 `schemaVersion: 3`，包含项目版本号、名称／备注、决定状态和参考研究状态。兼容旧格式1和2：读取时保留原存储不变，首次成功修改才写为格式3；失败不会覆盖旧数据。物理存储键和预览地址保持不变。决定状态即改即存，项目资料点击“保存修改”后写入本机。数据限定在同一浏览器、同一地址（协议、域名和端口）；没有跨设备同步，清除网站数据会丢失本机项目。多标签页使用浏览器 Web Locks 串行写入和版本号检查；不支持 Web Locks 的旧浏览器只保证同页面串行操作，不提供跨标签页原子保证。

样例按项目状态及原始结构数据导入，保留来源路径与 SHA-256。历史静态检查 134/134 来自既有结果，应用不会重新运行它。JSON 包含资料展示需要的摘要，Markdown 副本可直接阅读；运行时不读取受保护的原目录。

只有需要更新演示快照时，才在保有相邻参考目录的环境运行 `python3 scripts/import-demo.py`。脚本只读取参考资料、写入本应用 `src/mocks`。

## 验证

```sh
npm run typecheck
npm run lint
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
```

浏览器测试会在 3108 端口启动生产构建，每个测试使用隔离的浏览器存储。测试前需完成构建，不占用或清空个人浏览器数据。截图与失败追踪写入忽略目录 `test-results`。

目录选择场景使用完整Chromium和每测试独立的临时profile，测试后关闭并删除；本机打包Chromium的无痕上下文在读取OPFS目录引用时会退出，纯API最小复现相同。此fixture保留真实目录引用与IndexedDB往返，仅替代系统目录选择器返回值；不假称已操作用户电脑上的原生窗口。完整浏览器模式依据[Playwright文档](https://playwright.dev/docs/browsers)。

本轮五步调整的适用验证与独立审查结果以 `TASK.md` 为准；不沿用历史43项单元、42项浏览器通过作为本轮已验证证据。开发测试验证前端交互和数据保护，不代替用户验收、剧本审查或真人试玩。
