# 本间工作台 · 本机四步工作流

产品规范见[简易PRD](../01-产品需求/03-简易PRD-v0.1.md)，人工测试见[验收清单](../01-产品需求/06-当前验收清单.md)，本轮验证记录见TASK.md。

## 启动

Node.js 24、npm 11，首次`npm ci`，之后`npm run dev -- --port 3107`。生产预览用`npm run build`与`npm run start -- --port 3107`。只监听127.0.0.1，不对局域网公开。本机文件/OCR接口需要macOS的osascript、Swift、PDFKit、Vision和textutil；首次识别编译Swift，之后缓存复用。不需要安装PythonOCR包。

## 四步

1. 准备材料：真实上传到回环本机服务并读正文，必要时本机OCR；材料全部读取或由作者明确排除不可读项后，右下角「拆解大纲」。
2. 拆解与方向：模型返回带来源的大纲及2—5个改写方向，选方向、补充要求，右下角「生成蓝图」。
3. 创作蓝图：大纲、真相、角色目标/选择、轮次为主要内容；关系、事件、知情、证据、主持和终局折叠。修改预览并保存，旧审查失效，右下角「开始交叉验证」。
4. 交叉验证与导出：实际进度依次为设计门、全案生成、两路独审、两路互审、主模型复核；完整且无阻断问题才可「导出完整档案」。由服务端已通过快照生成ZIP，不接受浏览器自报通过或任意导出内容。打开保存位置由系统完成。

旧九阶段地址仍映射四步，旧项目记录不删。首页上传直接实际读文件后创建项目；读取取消不创建项目；最终跨LocalStorage/IndexedDB保存不是原子事务，失败保留项目ID和正文用于重试，避免重复创建。页面关闭会失去尚未保存的文件对象。

## 模型连接

本次实现蚂蚁平台连接、候选发现、固定小样测评、人民币预算账本与三模型自动分配，尚未用用户真实凭证产生调用。正式创作接口兼容OpenAI风格的chat/completions JSON Schema；不假定所有提供商均支持严格结构输出。

普通用户点击页面底部「配置模型」，服务器地址默认使用`https://maas-api.antdigital.com/v1`，只需粘贴API Key。保存仅记录平台连接，不外呼模型。之后的「读取候选模型」调用模型清单与公开人民币价格表，不生成内容；只有用户点击「开始受限测评」才进行最多4模型×3任务的短调用。完成后自动保存三个不同模型编号。受限配置文件为`runtime-data/studio-settings.json`（0600，目录0700，Git忽略），GET只返回安全字段和密钥存在标记，不返回密钥；换地址必须新填密钥。Key在粘贴及POST提交时会短暂存在页面内存和本机请求中，但不进入浏览器持久存储。

测评使用独立的`runtime-data/model-evaluation.sqlite`人民币账本：请求前原子预留，内部计划不超过800分，单次公开价估算增加20%安全余量，全部预算状态不超过1000分；价格读取10分钟后失效，未知或复杂价格不运行。平台完全不返回Token用量但正文完整时按字节上界和最高预留保守核算；部分、非法或超过预留的用量会停止。正文分片只采用明确的最终文本，不把推理内容当答案。新版每题提供4096 Token输出空间；`length`表示回答被截断，旧版900 Token记录保留为历史；评分契约已修订为juben-model-eval/1.1，旧分数不能混入新测评。真正的空正文、选项异常等响应会结算已知费用、自动跳过候选并在三轮内免费复核价格后补入其他候选；模型身份或用量无法核实时仍立即停止。费用结算、题目视图、候选排除和续测资格使用SQLite原子提交及跨进程版本校验。该账本不能保证平台最终结算绝对不超过10元，真实运行前应同时设置蚂蚁账号侧限额。测评输入是内置固定小样，不发送用户剧本。模型得分记录结构、证据、原创、格式、延迟、Token和按公开价格计算的费用；它只用于初始分工。已有运行记录后可查看或下载本机确定性生成的Markdown测评报告；中断报告明确缺项和待核对费用，不调用模型。

LiteLLM方案位于`infra/litellm`，固定已发布版本，不复制`litellm-litellm_internal_staging`源码。自动分配后会在Git忽略的runtime-data生成三个无密钥别名配置，并关闭LiteLLM自身的隐藏重试，避免绕过工作台的人民币账本和候选排除记录。评分、截断识别和自动换候选由工作台负责；LiteLLM负责后续统一接口。本批尚未自动启动代理，正式工作流暂时使用蚂蚁官方兼容接口；代理启动、健康检查和进程恢复是下一后端批次。

也可使用本机`.env.local`（Git忽略）或进程环境设置；环境变量整组优先，存在时页面只读，避免两个来源混用密钥：

- `STUDIO_API_BASE_URL`：兼容接口基础地址（例如本机LiteLLM的/v1）
- `STUDIO_API_KEY`：仅服务端读取
- `STUDIO_MAIN_MODEL`：主模型编号
- `STUDIO_REVIEW_A_MODEL`、`STUDIO_REVIEW_B_MODEL`：两个不同审查编号，三者不可相同

配置完成重启服务。配置存在不表示已实测可用。输入正文会发往你配置的服务，须先明确服务、模型与费用，不能把真实密钥提交仓库。未配置返回503且零外呼，前端主要AI按钮不可用。

Skill工作流以juben-design/1.0约束嵌入服务端编排提示，未声称模型实际执行本机Skill工具。正文指令视为数据；证据可回查、全链通过和玩家/主持隔离均作为门槛；模型判断仍可能有误，不能替代真人试玩。

## 存储与恢复

新正文/创作内容通过独立Service存IndexedDB，CAS revision防覆盖；旧项目metadata在LocalStorage。输出目录本机注册ID→路径写入`runtime-data/directories.json`，目录0700、文件0600，对前端只返回名称/opaque ID。Git忽略runtime-data、上传、构建产物和密钥。实际原文件不修改。

模型任务先持久保存请求UUID，再外呼；同ID恢复不重复调用。任务及通过快照当前服务端内存保留2小时，重启会失效；404明确提示重新处理，可能已产生此前调用费用。状态失败时不会自动重新调用。此版本不是完整生产后端，没有账号、数据库、长期任务队列或云备份。

导出为含Markdown正文/蓝图JSON/审查报告的ZIP，按角色及主持分区；现不提供Word/PDF转换或真人试玩录入。目录仅在点击导出后写入，排他创建新文件避免覆盖已有档案。

## 处理限制

每批最多2000份存储；单文件25MB、单正文30万字、PDF60页、图像4000万像素。模型单次最多200份材料，总输入600KB（UTF-8 JSON，包括中间报告），单回复2MB，每调用120秒；2个并发任务、24个保留任务。超限明确拒绝，不截断。音视频尚未转写、压缩包尚未解包。大型剧本分块研究与上下文管理仍须补充，不能把超限结果称作完整分析。

## 验证

`npm run typecheck`、`npm run lint`、`npm run test`、`npm run build`、`npm run test:e2e`。

原五步Mock的历史86条界面场景保存在tests/legacy-e2e，已不适用四步UI，不计作当前通过；底层旧单元仍运行。当前E2E实际TXT读取与浏览器存储真实执行；模型/系统选择窗口采用边界fixture，不外呼、不自动选择用户目录。PDF/图片/RTF读取另有真实本机组件单元验证。

## 首页拖拽与换本

首页整块拖拽区替代说明卡和最近项目表，已有项目仍在侧栏/项目列表。支持目录递归和读取全部批次，保留相对路径，滤掉系统文件。目录API遵循[浏览器目录读取说明](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemDirectoryReader/readEntries)，每次读到空批次才结束，避免遗漏超过100个条目。深度/数量保护会整批拒绝，不默默漏文件。

项目已有输入时按钮为“更改文件夹”。读取完新批次才CAS替换；任何error或没有成功正文会拒绝替换，unsupported项可登记但需处理/排除才能分析。取消读取或存储失败保留旧批次。进入保存阶段按钮禁用取消，避免误报。替换仅影响当前输入与关联有效性，不改项目名、输出位置或原文件。旧蓝图和审查保留但过期。

### 评分契约修订与历史报告

v1.1 明示三道题的数组条数、字数与唯一性要求，引用允许保留原句标签及句末句号；普通“事故”一词不作为照搬证据。字段校验失败会列出固定中文路径/原因，不把格式拒收当作完整能力结论。评分仍是固定小样的程序规则，不是完整Skill执行评估。

旧轮停止后提供“准备修订版测评计划（免费）”：核对候选与价格，在SQLite事务中归档旧视图、建立独立新成绩列表；已有已核算/待核对费用保持累计，仍受8元内部计划和10元估算限额保护。必须再次点击“开始受限测评”才调用模型；新计划开始前会原子核对版本、运行权与结转账本，防止多页面重复调用。上一轮报告可下载，旧原始答案未保存，不能免费补算新分数。计划超过10分钟可免费刷新价格，保留原归档和费用。

每次新响应只额外保存结束标志、最终正文字符数、推理字符数、平台明确返回的推理Token数量以及请求输出上限；不保存原始答案或隐藏推理文本。历史记录没有这些元信息时标明未知，不把新版截断一概称为旧版问题。
