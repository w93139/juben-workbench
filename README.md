# AI剧本杀原创改写工作台

简体中文创作工具，按五步组织：**准备材料 → 确定创作方案 → 设计故事 → 生成与检查 → 试玩与导出**。新作从上传想要改写的完整剧本文件夹开始，第二步比较原创大纲和写作方向；不再选择空白或演示副本。

当前是本地Mock前端原型。A基础、B参考研究、C故事蓝图、D生成与检查已完成开发；按A—E五批等权计算，原型进度为 **4/5（80%）**，不含真实后端。A与C用户测试通过，B未单独记录正式结论，本轮请体验D。E试玩与导出待开发。

选择方向并采用大纲后进入“设计故事”，支持编辑人物、关系、时间线、信息、线索、轮次、主持与终局，保存草稿和命名历史版本。关系图跟随关联更新，基础检查提示缺项、断链和因果循环；这些提示不等于AI审查或真人试玩。真实后端、OCR与模型调用尚未实现。

顶部保留当前页面、一个主操作、修改决定和一个检查入口，下方具体内容单独滚动。方向允许先存草稿，推荐不自动确认；项目输出目录统一设置，平时只显示位置和更改入口。旧九阶段地址、项目数据和默认输出子目录继续兼容。

## 仓库保存范围

按用户授权公开的仓库保存产品需求、应用代码、类型与服务接口、演示快照、测试与开发计划。演示快照含《名字之外》的故事摘要和机制研究摘录，不是空数据结构。

原始参考材料、完整历史审查目录、agent-blueprint参考工程、个人Skill、依赖、构建产物、测试截图、密钥与真实数据库不上传。`scripts/import-demo.py`是可选的本地重建工具，需要仓库外的只读原资料；普通启动、构建和测试不运行它。

网页中创建的项目当前保存于浏览器LocalStorage，目录授权引用保存于IndexedDB。GitHub同步不会备份这些状态，也不是数据库服务。真实项目持久化、文件存储与恢复列入后端计划。

每轮开发完成适用验证后，通过`python3 scripts/sync-github.py --message "说明这次更新"`提交并同步。也可在Mac双击`同步到GitHub.command`。没有安装后台监听程序，每次保存文件不会自动上传。

代码开源范围与素材权利见 [LICENSE](LICENSE) 和 [NOTICE.md](NOTICE.md)。凭证保护、API接入边界与泄露处理见 [SECURITY.md](SECURITY.md)；不要提交或在浏览器中保存真实模型密钥。

项目左侧只列剧本，五步创作流程在项目顶部。用户项目标题旁小笔可改名；首页上传与左侧“＋”直接选择完整剧本文件夹，自动命名建项目；项目内导入只补充材料，输出选好后自动记住。界面以#333333为主色，搭配暖白、浅暖灰和少量赭色。

“生成与检查”支持六类模板正文、版本编辑、模拟双模型意见和分歧处理，改稿后另开复查。正文与意见均明确标注Mock，未调用真实模型或Skill，不能代替真人试玩。

完整文件夹入口只登记文件信息，不读正文。架构框架保持待真实识别，三个大纲方向是独立通用Mock建议，不冒充从上传剧本得出的结论。原始档案保留但不混入我的项目，既有用户项目不删除。
