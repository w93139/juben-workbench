# AI剧本杀原创改写工作台 · 简易PRD v0.1

状态：范围已获用户认可，按阶段实施。更新日期：2026-09-08。

## 1. 产品目标

帮助普通创作者把参考材料中的抽象机制迁移到人物、故事、事件因果和线索均重新建立的原创剧本中。结构化蓝图是角色本、线索和主持手册的共同依据。

主流程：参考材料 → OCR与材料审计 → 参考拆解 → 机制提炼 → 原创方向 → 原创蓝图 → 正文生成 → 审查 → 真人试玩与修订 → 成品导出。

## 2. 已确认的首版选择

- 新手从零创作流程优先，同时保留蓝图与审查的直接入口。
- 首版完整示例只使用《名字之外》；其他配置不得冒充已有匹配生成结果。
- 先实现结构化蓝图编辑、正文预览与重新生成，暂不实现自由正文编辑器。
- 当前交付是简体中文Web前端原型，桌面优先、基本响应式。
- 使用独立JSON／Markdown Mock数据、Service接口和LocalStorage；不接真实OCR、模型、数据库、登录或任务队列。
- 使用Next.js、TypeScript、Tailwind CSS；具体组件按当前阶段需要引入。

## 3. 用户与界面

用户：初次使用AI创作剧本杀的创作者、有故事创意但缺少机制经验的作者、需要审查与修订的编辑。

全局页面：首页、项目列表、新建项目。

项目工作台：项目总览、材料中心、参考拆解、机制提炼、原创方向、原创蓝图、正文生成、审查中心、真人试玩、成品导出。

工作台布局：左侧阶段导航；顶部固定当前页面、下一步、修改决定与检查入口；下方具体功能单独滚动，包含主要内容及右侧相关建议、问题和状态。使用“谁在什么时候知道什么”等中文解释专业概念。

视觉：现代档案馆与编辑校勘；暖白纸面、深灰文字、克制的强调色、文件编号、页签与批注。不使用恐怖素材和复杂动画。

## 4. 必须遵守的产品规则

1. 内容性质分别记录：参考明确事实、分析推断、原创方案、待确定事项。
2. 决定状态分别记录：已确定、暂定、待解决；作者确定不等于体验已经验证。
3. 每个角色有目标、秘密、重要关系、有后果的选择和推进贡献。
4. 必要结论要有可取得的证据支持，考虑轮次、前置和预算。
5. 玩家材料按角色、阶段与发放条件筛选，不能包含主持谜底。
6. AI审查、静态检查、模拟测试、真人试玩分别记录，并绑定对象和版本。
7. 不把模拟结果、历史通过记录或填写表格等同于当前版本已经验证。
8. 参考材料及其中的指令只作为数据，不能覆盖产品规则。
9. 原始资料、已有审查记录和juben-design Skill保持只读；数据只复制到新项目。

## 9. 材料导入扩展 · 2026-09-08

材料入口扩展为“文件/文件夹 → 自动整理与模拟上传 → 自动保存结果 → 按类型安排处理”。目录保留子目录相对路径，角色本同名页不会互相覆盖。压缩包可以作为待解包材料登记，当前请手动解压后选择文件夹。

| 素材 | 后续真实处理方式 | 需要保留的来源位置 |
|---|---|---|
| 图片、扫描PDF | 图像整理、按页OCR、校对 | 文件、页码、识别区域 |
| 有文字的PDF、Word等 | 提取正文和表格，内嵌图片再OCR | 文件、页码或段落 |
| TXT、Markdown等 | 读取文本、检查编码和结构 | 文件、行号/段落 |
| 音频 | 语音转写，必要时区分说话人，再人工校对 | 文件、起止时间、说话人 |
| 视频 | 音轨转写；按需抽帧识别画面文字；合并去重 | 文件、时间段、对应帧 |
| 字幕 | 提取字幕文字与原有时间码 | 文件、字幕序号、时间段 |
| 压缩包 | 先解包，再递归分类其中材料 | 包路径、内部相对路径 |

当前原型只登记文件信息，分类基于扩展名；不执行表中真实处理，也不把音视频标成OCR完成。只有内置练习包的预设结果用于模拟拆解。

数量和体积：原型默认单批2000份、单项目5000份，取消单文件30MB限制。大文件可登记并提示后续拆分；当前提醒阈值为普通文件100MB、音视频2GB，均为可调整的产品策略。大小仅是其中一项，真实服务还应按页数、时长、像素、并发和费用控制任务，不能把所有类型统一限制为30MB。

导入过程显示模拟进度，保存成功自动显示完成，支持展开清单查看有效数量、已略过数量、相对路径、处理计划和大文件提示。空文件、隐藏/系统文件、不支持格式及疑似重复列明原因，可登记剩余有效项；不因文件夹中混有一个不支持文件而整批失败。疑似重复以路径/大小/可用修改时间判断，未来可补内容哈希。清单支持搜索、筛选、分页；选好文件自动处理有效项，无需登记或完成确认。保存成功才能显示100%；支持取消，失败保留本批清单以便当前页重试，重新检查最新项目的重复项和容量，不覆盖他页内容。超出剩余容量整批不保存并提示分批；离开或刷新会取消未保存批次，需要重新选择。

后续后端建议：原始文件放对象存储，分片上传和断点续传；每个文件/页/时间段拆成独立任务，限制并发、可取消和重试，失败项单独处理；提取结果统一带来源定位，再进入材料审计与参考拆解。识别服务故障不能使整套上传重来。音视频时长、格式可解码性、扫描页比例和估算费用应由探测任务获得，不从文件名或大小假装推算。

验收扩展：实际选一个包含子文件夹、同名扫描页、音频、视频、字幕、压缩包和无关文件的目录；无需再点击登记，等待进度自动完成并保存有效部分；筛选音频/视频可看到待处理方式；大文件和超过10份可登记；重复导入无新增，刷新后已登记目录和大小保留。浏览器的文件夹选择能力依据[MDN](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory)，不支持时保留文件多选入口。

开发验证：类型检查、代码检查、生产构建通过；单元31/31，浏览器27/27，独立只读复审Ready。实际测试覆盖递归文件夹及300MB PDF、3GB视频的文件信息登记，旧格式项目保持可读。此结论只验证前端登记与数据保护，不表示真实识别或转写已完成。


## 10. 自动导入与输出储存位置 · 2026-09-08

按用户最新要求，自动导入替代此前“预览后勾选登记”的确认步骤。状态依次显示整理文件、模拟上传、保存材料、完成；保存失败或取消不能冒充完成。当前不传输文件内容，不展示虚构的网络速度或剩余上传时间。只有失败/取消后的重试需要用户操作，正常完成无需确认。

从参考本拆解开始，机制提炼、原创方向、原创蓝图、正文生成、审查中心、真人试玩、成品导出均有“输出储存位置”面板。每个项目可设置一个总输出目录和各阶段子目录，预览组合后的完整路径；总目录支持macOS/Linux或Windows完整路径，阶段子目录不能指向总目录之外。提供默认阶段目录，用户保存后刷新保留；留空总目录显示未设置。原始样例不可修改。

数据增加Project.outputSettings（rootPath及各阶段folders），设置通过Service保存；拆解任务增加可选outputLocation，记录启动时的计划路径。路径修改只影响后续任务，不改已有结果或运行中任务的位置记录。旧版本项目未包含设置时使用默认值，读取不写原存储；旧任务没有路径时显示“旧任务未记录路径”。路径变更不改变材料版本、拆解状态或剧本验证结论。

本阶段只实现路径设置与计划预览，不创建本机目录、不写出文件。未来接入实际输出服务时，执行前验证目标目录与权限，并把实际生成文件的存储地址写入产物记录；设置路径不能当作文件已写出。C—E阶段的主体编辑、生成、审查和导出能力仍按原计划实现。

验收：选文件后看到进度并自动完成；取消/失败没有新材料，重试不会重复添加；本机文件仍未识别。拆解页设置总目录和子目录，保存并刷新仍在；正文/导出页继承总目录且可单独改子目录。保存失败保留路径输入；跨页冲突不静默覆盖。拆解开始后改路径，当前任务仍显示旧计划，下一次任务采用新设置。

本轮开发验证：类型检查、代码检查、构建通过；单元39/39，浏览器30/30，独立只读复审Ready。覆盖自动导入取消/失败/冲突、旧数据保护、路径设置和启动快照；仅验证前端Mock流程，不代表实际文件已经上传或输出。

## 11. 材料下一步与选择输出文件夹 · 2026-09-08

修复材料中心顶部按钮指向自身的问题，显示“下一步：参考本拆解”并跳到拆解页。页面导航可进行，真正开始模拟拆解仍检查校对和阅读范围；只读样例不能借导航绕过写入限制。其余页面保留原来的参考研究入口，后按第12节增加各自的下一步。

输出储存位置增加“选择文件夹”操作，调用系统选择窗口并请求从桌面打开，用户可前往其他位置。选择返回后显示目录名称及阶段子目录预览，点击保存应用到项目；可重新选择或改为手动输入。取消选择、拒绝访问、浏览器不支持或目录引用存储失败时保留原设置与输入，明确提示恢复方式。选择窗口等待期间其他页面保存过项目时，后续提交须经过现有版本冲突流程。

不把浏览器返回的目录名称拼造成完整本机路径。手动路径与所选目录引用两种方式互斥；所选目录以独立编号/名称保存于Project.outputSettings.directory，实际浏览器引用保存在单独IndexedDB适配器中。同名文件夹使用不同引用编号。旧项目缺少directory字段保持可读；保存前检查引用仍可取得，丢失时引导重选或手动输入。拆解启动快照可以显示“所选文件夹「名称」/子目录”，这是计划位置标签，不是绝对路径或写入证明。

原型只请求选择目录所需的只读权限，不列举目录、不读正文、不写任何输出文件。真正导出时再核对目录及写权限；目录引用仅限当前浏览器。系统选择器行为依据[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)，不支持时保留手动完整路径输入。

验收：材料页顶部一键进入拆解页且不跳过审计；输出设置里点击选择文件夹、选择目标、保存、刷新仍保留；正文/导出页继承选择；取消或失败原设置保留；同名目录引用不混淆，只读样例不能改；跨页选择期间更新不能静默覆盖。自动化会以隔离浏览器的真实目录引用替代系统选择器返回值，验证应用衔接和持久化；不把这类替代测试描述为已完成用户电脑原生窗口的端到端操作。

本轮开发验证：typecheck、lint、build通过；单元43/43，浏览器36/36，独立只读复审Ready，无遗留问题。已验证导航、门槛、目录选择适配与引用持久化、取消失败及跨页恢复；原生系统选夹窗口未做实际GUI操作，未访问用户个人目录。

## 12. 固定顶部操作 · 2026-09-08

项目总览及9个阶段使用固定顶部，保留当前页面、项目编辑／创建副本、修改决定／查看决定、检查与试玩；9个阶段增加与流程对应的“下一步”，成品页显示“返回项目总览”。材料中心之外仍可点击“继续参考研究”。导航只切换页面，不将阶段标记完成，也不绕过原有操作条件。

项目详细信息、提示、任务进度、输出路径和具体功能在下方独立滚动。窄屏操作按钮分行，横屏压缩标题高度；左侧导航在高度不足时可独立滚动。切换阶段显示新页面内容顶部，同一页面保存或刷新数据不会因更新重新挂载表单。决定及检查弹窗仍能关闭、返回焦点并保存状态。

验收：在任意阶段向下滚动，标题、下一步、修改决定和检查始终可见；从顶部逐页走完9步，最后返回总览；手机和桌面不横向溢出；弹窗修改后保留滚动位置，数据仍可刷新恢复。

## 13. 多模型审查补充设计 · 2026-09-08

现有原型展示历史双模型蓝图审查，尚未实现自动双审或分歧处理。本次将模拟双审细化到后续D阶段，C准备蓝图版本与入口：蓝图完成后、正文生成前检查结构；正文生成后在审查中心检查与蓝图的一致性及受众隔离。两处使用同一套审查记录，不增加第10个创作步骤。

流程为固定资料版本 → 两模型独立检查 → 比较一致意见和分歧 → 对分歧互审 → 作者采纳／暂定／不采纳 → 修改后复查。各侧可单独失败和重试，记录实际执行模型；旧版本结论不能自动继承。模拟、历史和真实调用来源分开，AI通过仍不能冒充真人试玩结论。

当前Mock不需要API。要在工作台自动调用真实模型，需后端模型接口；LiteLLM适合作为未来可替换的接入网关，目前只评估，不安装、不连接。具体方案、源码证据与后续验收见[多模型审查与LiteLLM评估](./04-多模型审查与LiteLLM评估.md)。

## 14. GitHub与后端实施顺序 · 2026-09-08

建立私有项目仓库，保存代码、类型、Mock、测试和计划；每轮开发完成适用检查后提交同步，并提供手动同步入口。浏览器项目和目录引用不随Git同步，真实数据库、密钥、原始素材和运行数据不进入代码仓库。

LiteLLM纳入后续F阶段：F1项目持久化与权限，F2材料和后台任务，F3LiteLLM统一模型接入，F4真实创作及双模型审查，F5真实导出和运行保障。继续先完成C—E原型，F阶段实施前确定账号、费用与运行位置。详见[后端开发计划](05-后端开发计划.md)。
