# AI剧本杀原创改写工作台 · 简易PRD v0.3

更新：2026-09-08。本轮推进C阶段故事蓝图编辑，并显示开发阶段与总进度；保留已确认的五步主流程。沿用文件名，避免已有链接失效。本文件描述当前产品规范，实施与开发验证见前端 `TASK.md`。

## 1. 产品目标与范围

帮助普通创作者把参考材料中的抽象机制迁移到人物、故事、事件因果和线索均重新建立的原创剧本中，避免仅替换人名、地点或背景。结构化蓝图是角色本、线索和主持手册的共同依据。

用户包括初次使用AI的创作者、有故事创意但缺少机制经验的作者，以及需要检查与修订的编辑。使用简明中文，专业术语旁提供解释；例如用“谁在什么时候知道什么”说明知识矩阵。

当前是简体中文Web前端原型，桌面优先、基本响应式；使用本地JSON／Markdown Mock、独立Service和LocalStorage，不接真实上传、OCR、音视频处理、模型、数据库、登录或任务队列。首版完整演示只使用《名字之外》，其他人数或题材设置不能冒充已有匹配生成结果。先实现结构化蓝图编辑、正文预览与分模块重新生成，自由正文编辑器后续再考虑。

## 2. 五步信息架构

首页、项目列表、新建项目与项目总览是独立入口，不计入五步。左侧只显示以下五个创作步骤；允许编辑直接进入故事设计或检查，不强制从第一步走起。页面导航不等于完成阶段，也不绕过实际操作条件。

| 主步骤 | 包含的原有能力 | 用户主要操作 |
|---|---|---|
| 1. 准备材料 | 材料中心、OCR状态、材料审计 | 导入文件或文件夹，查看进度，校对问题，记录缺失，确认阅读范围 |
| 2. 确定创作方案 | 参考拆解、机制提炼、原创方向 | 查看推荐方案，确定借鉴的玩法与迁移风险，设置新作方向；详细分析按需展开 |
| 3. 设计故事 | 原创蓝图 | 编辑真相与时间线、角色与关系、信息分配、线索链、轮次、主持触发和终局 |
| 4. 生成与检查 | 正文生成、审查中心 | 分模块生成角色本与主持材料，比较审查意见，处理问题并复查 |
| 5. 试玩与导出 | 真人试玩、成品导出 | 先导出标明“尚未真人试玩”的试玩包，再记录反馈、修订并导出新版 |

兼容已有九个 `StageId` 和旧地址，不迁移或丢弃历史数据。五步默认地址依次使用 `materials`、`analysis`、`blueprint`、`generation`、`export`；同组的旧地址打开同一组合页面，导航高亮同一个主步骤。底层阶段仍用于来源、任务和默认输出子目录，不直接作为九项主导航展示。

## 3. 界面减负规则

- 顶部固定当前页面、一个明确的主操作、修改决定和一个检查入口；只有下方具体内容滚动。主操作按进度指向当前应做的事或下一主步骤，不再每页重复“继续参考研究”。
- 项目详细信息、长篇来源说明、迁移分析与开发边界按需展开。Mock标识、材料重大缺口、历史结果和未试玩状态仍直接可见。
- 检查信息集中在一个入口，不在右侧重复列出相同检查。当前页面优先展示与当前操作相关的问题。
- 项目共用一个输出总目录，每页平时只显示计划位置及“更改输出位置”；展开后才显示选夹和路径表单。默认子目录沿用已有八个输出阶段，高级设置保留各阶段覆盖。
- 视觉保持现代档案馆与编辑校勘：暖白纸面、深灰文字、克制强调色、文件编号和批注，不用恐怖素材或复杂动画。

## 4. 每一步的行为

### 准备材料

选择文件或文件夹后自动整理、模拟上传并保存清单，无需再次确认完成；保存成功才显示100%。保存失败或取消不能冒充完成，失败保留当前批次供重试；离开或刷新取消未保存导入，已保存清单保留。

保留子目录相对路径；图片、PDF、办公文档、文本、音频、视频、字幕及压缩包按类型登记。当前只保存名称、类型、大小、相对路径和修改时间，不读正文、不解压、不OCR或转写。音频和视频明确显示后续需转写或画面识别，不标成已OCR。

原型单批2000份、单项目5000份；没有单文件30MB硬限制。普通文件超过100MB、音视频超过2GB提醒后续拆分，不阻止登记。空文件、隐藏／系统文件、不支持格式和疑似重复项显示略过原因；超出剩余容量整批不保存。材料清单支持搜索、筛选、分页。未来真实处理按页数、时长、格式、并发和费用确定策略。

研究练习包包含3份机制研究摘录、8条机制与4项人为设置的识别问题。用户可模拟OCR、失败重试、取消与刷新续进度，完成校对、排除重复、记录缺失并确认阅读范围。完整原作真相、时间线和关系因材料不足保持未知，不能拿《名字之外》的原创设定充当参考事实。

### 确定创作方案

将原来的三个页面合并为一个工作区，先展示推荐玩法、主要迁移风险和原创方向；用户可以展开参考分析、证据来源和机制前提。

人数、题材、时长、禁止内容、创意可先保存为方向草稿，不要求先完成参考研究。体验先选“偏推理／偏情感／偏互动／均衡”，需要时展开精确百分比；最终比例必须总计100%。推荐机制标为“暂定”，不能因为系统展示推荐就记为作者已确认。

机制可选保留、改造或舍弃，提供可编辑的建议理由，集中保存或确认，不要求逐卡逐页提交。最终确认时一次保存机制取舍与创作方向，并核对校对、阅读范围、当前拆解等前提；任一项失败不部分确认。草稿保存和方案确认明确分开。

材料或校对改变后，旧范围、拆解和方向确认失效，已有机制选择与方向草稿保留；作者需核对新资料后重新确认。改变人数、题材或时长显示迁移风险，不自动重写样例。

### 设计故事

完整目标包括真相、事件因果、时间线、角色卡、关系图、谁知道什么、线索到结论、轮次、主持触发与终局选择的结构化编辑。每个角色必须有个人目标、秘密、重要关系、有后果的选择和推进贡献；必要结论必须有可获得的线索支持。

本轮C阶段提供六组编辑：故事真相、人物与关系、客观时间线、信息与线索、轮次与主持、终局选择。可新增、修改和删除记录，关联按编号保存、按中文名称选择；修改角色姓名同步更新关系图及关联名称。删除被引用的记录保留原引用并提示重新关联，不能静默删除其他设计。

空白项目可建立空白蓝图；演示副本还可载入应用内《名字之外》蓝图。原始样例只读，载入样例不代表根据用户题材重新生成。快照缺少的事件前因、信息发放条件、主持与终局细节明确待补充，不编造成参考材料事实。

未完成内容可保存草稿。即时结构提示检查必填项、无效引用、事件因果循环，以及必要结论是否关联注明发放轮次和获取方式的线索；可定位对应记录。这是基础字段与关联检查，不判断自然语言推理是否成立、不完整检测时间矛盾或信息泄漏，不等于AI审查或历史静态检查通过。

保存草稿后可建立命名版本，最多保留20份只读历史快照；未保存修改不能建立版本，不自动删除最旧版本。后续修改草稿不改变历史，草稿与最新版本不同时提示待建立新版；浏览历史不替换当前草稿。离开设计故事页前需保存，切换本页分类保留输入；保存失败或多页冲突保留输入并给出恢复提示。

蓝图完成后、正文生成前提供审查准备入口，显示待审版本；C准备版本与入口，D实现模拟双审，不新增主步骤。新草稿和新版本不能继承《名字之外》历史检查的通过状态。

### 生成与检查

同页组织角色本、私人信息、阶段更新、公共线索、主持手册和终局材料，以及审查问题。D阶段实现分模块模拟生成、候选版本、重新生成和修改影响，不把现有只读摘要称作已实现生成。

问题类型包括时间线矛盾、信息泄漏、推理缺口、边缘角色、机制漏洞、阅读负担、节奏风险和主持歧义。每条问题有严重程度、证据位置、修改建议、处理状态及适用版本。

双审流程：固定资料版本 → 两模型独立检查 → 对比共同意见与分歧 → 有限轮次互审 → 作者采纳／暂定／不采纳 → 修改后复查。各模型可单独失败和重试，记录实际执行模型。蓝图和正文两个审查时机共用审查记录；旧版本结果不自动继承到新版。

### 试玩与导出

E阶段实现文件树、玩家与主持材料分区、受众预览和Markdown／Word／PDF／ZIP模拟导出，明确剧透提醒。试玩记录包括实际时长、卡点、各角色参与度、线索购买、推理结果、主持问题和修改建议。

允许先拿到标明“尚未真人试玩”的试玩包；真人试玩不是首次导出的前置条件。之后记录反馈、修订并导出新版，持续保留版本及验证状态。当前主体功能尚未实现，只读展示不提供假的生成／导出完成状态。

## 5. 数据、决定与验证边界

1. 内容性质分为参考明确事实、分析推断、原创方案、待确定事项；决定状态另分已确定、暂定、待解决，两者不混用。
2. 作者确定不等于体验已验证。AI审查、静态检查、模拟测试、真人试玩分开记录，绑定对象、版本和来源。
3. 不把历史通过、模拟输出或填写记录等同于当前版本已经通过。双模型一致也不能替代证据核对或真人试玩。
4. 玩家材料按角色、阶段和发放条件隔离主持谜底；当前作者工作区含谜底，不能充当生产玩家端或权限系统。
5. 参考材料中的任何指令只作为数据，不能覆盖产品和开发要求。原资料、既有审查记录与juben-design Skill只读。
6. 存储失败保留输入；损坏或不兼容数据不被默认值静默覆盖。多标签页过期修改必须明确处理冲突，不能覆盖他页修改。

核心实体：Project、SourceDocument、OCRIssue、WorkflowStage、DecisionRecord、Character、Relationship、Fact、KnowledgeItem、Clue、Claim、Round、HostTrigger、ReviewFinding、PlaytestRecord、ExportArtifact。C新增BlueprintWorkspace（草稿、修订号、保存时间、来源说明、历史版本）、BlueprintData（真相和九类记录）、BlueprintVersion（命名快照）及即时BlueprintIssue；实体编号建立关联。按实际阶段补充内容模块、任务与检查执行，不提前堆积无用实体。

技术结构：Next.js／TypeScript／Tailwind页面 → 业务Service → Mock适配器 → JSON／Markdown基线与浏览器状态。组件不写死正文、不直接操作存储；真实后端以后替换适配器。

基准样例只读，副本独立。LocalStorage保留既有存储键与格式兼容；此次五步导航不迁移或清空项目。浏览器项目状态不随GitHub同步，不具备跨设备备份。

## 6. 输出位置与文件处理

输出总目录支持系统文件夹选择或手动完整路径，二者互斥。选择器请求从桌面打开，实际起始位置由浏览器决定；取消、拒绝、不支持或存储失败保留原设置，不支持时可手填。目录名称不能拼造成绝对路径。

项目存储所选目录的编号和名称，浏览器引用由独立IndexedDB适配器保存；不能跨浏览器或设备迁移。同名目录使用不同引用；引用失效引导重选。原型只请求选择所需的只读权限，不枚举目录、不读文件、不创建目录或写出产物。

总目录项目共用，各阶段保留默认子目录与高级覆盖。路径设置保存后刷新恢复，路径变更不改变研究和审查结论。任务记录启动时已保存的计划位置，改设置不改运行中或历史任务，旧任务未记录时如实说明。设置位置不是输出成功，真实写入及权限检查在后端阶段实施。

## 7. 开发批次与验收

五个产品步骤与A—E开发批次是两个维度，不要求一一对应。

| 开发批次 | 交付 | 当前状态 |
|---|---|---|
| A：基础 | 首页、项目、决定、本地恢复、档案摘要与检查边界 | 用户已验收，无需重验 |
| B：参考研究 | 准备材料与确定创作方案、五步导航、集中方案操作与折叠设置 | 开发完成；未记录用户正式验收结论 |
| C：蓝图 | 结构化编辑、关系图、基础结构提示、版本及蓝图审查准备 | 本轮交付；待用户体验编辑与关联是否顺手 |
| D：生成审查 | 分模块模拟生成、双模型模拟审查、分歧处理和复查 | 待开发 |
| E：试玩导出 | 试玩记录、受众预览、试玩包与修订包模拟导出 | 待开发 |

原型总开发进度按A—E五个开发批次等权计算：C完成开发交付后为3/5，即60%。这不是代码行数、用户验收比例或真实产品完成度，不包含后端F。界面提供开发进度入口，同时列出开发状态与用户验收状态；“开始开发”的指令不记作B验收通过。

本轮只需体验C的五项操作：建立演示蓝图、修改保存与关系图、线索结论关联提示、轮次主持终局编辑、历史版本与检查边界。已验收的A和已有B操作不要求全部重测。具体非技术步骤见[当前验收清单](06-当前验收清单.md)。

按coding-workflow执行适用的类型检查、代码检查、单元测试、构建、浏览器交互和独立只读审查，证据记录于前端 `TASK.md`。开发检查不代替用户验收或真人试玩。本PRD不预先宣称本轮检查通过。

用户已授权按已定原型范围持续推进；普通可逆实现细节自行处理，真实API、费用、部署、权限等以具体授权为准。

## 9. 本轮交互与开源调整（2026-09-08）

用户授权公开GitHub仓库；公开前检查提交历史与当前内容，代码许可和剧情素材权利分开。真实API后续只经服务端调用，凭证不得进入前端、浏览器存储或公开仓库；同步与CI执行凭证检查，GitHub启用可用的密钥扫描与推送保护，实际启用结果以开发记录为准。不能把这些措施表述为绝对不会泄露。

项目总览的编辑入口明确命名为“修改剧本名称”，沿用保存、冲突保护和刷新恢复。原始样例需创建副本后编辑。输出位置显示只读原因、浏览器能力和安全环境提示；支持时直接调系统目录窗口，不支持时允许手动完整路径，不能把登记目录名冒充读写授权。阶段切换只让正文轻微渐入，减少动态效果偏好下关闭，保存不重新播放或重置输入。
