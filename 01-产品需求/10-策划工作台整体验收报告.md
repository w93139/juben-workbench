## R1：限定/否定描述仍被当作公共线索（失败）

代码：`03-前端原型/src/domain/handoff-package.ts` 的 `classifyClue`。公共词正则匹配子串，不能表达否定、限定或条件冲突。

调用真实源码函数的自造反例结果：

| access | 实际分类 | 实际公共卡 | 包就绪/自检 |
|---|---|---|---|
| 不公开，仅交给甲 | public | 收入该线索 | ready，issues=[] |
| 公共区域搜证后仅甲可领 | public | 收入该线索 | ready，issues=[] |
| 所有线索由主持保管，仅甲可领 | public | 收入该线索 | ready，issues=[] |

影响：交接任务书会给外部作者错误的发放范围。它是方案正确性问题，不需要实际写出正文或组织试玩即可判定失败。

关闭标准：不能再以“含某个公共词”证明公共权限。明确的结构化分发信息优先；旧自由文本若无法确定则进入主持待确认项，不进入公共卡，且不遗漏线索。生成和自检均应覆盖上面三类反例、指定角色及明确公共的正例。不得仅继续扩大关键词表来宣称任意自然语言已可安全分类。

## R2：作者修订绑定了材料版本，未绑定实际分析结果（失败）

代码：`src/services/studio-client.ts` 的 `authorEditsCurrent/effectiveAnalysis`，以及 `src/domain/studio-job-update.ts` 的分析完成路径。

实际调用 `applyStudioJobView` 完成同材料重新拆解后：

```text
sourceRevision = 2
analysisSourceRevision = 2
authorRevision = 2
state.analysis.outline = 本轮新分析
authorEditsCurrent = true
studioJobInput(blueprint).analysis.outline = 旧作者大纲
蓝图请求中的方向 = 旧作者方向
```

原因：同材料重拆不会递增材料版本。现有测试直接把 `analysisSourceRevision` 从 2 改成 3，不能代表真实同源重拆路径。

升级兼容还存在同类问题：上一版已保存的作者内容缺少新 `authorRevision` 字段时，加载后该字段为 null，内容不再被采用，旧修订提示也不显示；文本尚在存储字段中，并非已被删除。

关闭标准：为实际分析结果提供可辨认的版本/标识或可靠的依据绑定；同源新分析、换材料、旧字段升级均不得静默误用或隐去作者内容。旧修订和暂存草稿应保留且明确标为旧依据，显式采用后才能成为新依据。回归必须调用真实分析完成路径，不能只手工改版本数字。

## R3：保存其他字段仍会静默清除未保存作者大纲（失败）

代码：`src/components/studio/analysis-edits.tsx` 以任意 `state.revision` 变化重置编辑器，并调用 `clearDraft(id)`。

隔离 Playwright 的实际操作：在分析页输入作者大纲但不保存 → 修改同页“补充创作要求” → 失焦自动保存。该反例 1 failed，退出 1，证据为：

```text
expected outline = 第三轮验收：这段作者输入必须保留
actual outline = 原始灯塔材料的事件和信息顺序。
revision = 2
authorOutline = null
localDraft = null
冲突提示数量 = 0
```

同类静态缺口：暂存草稿仅有内容、无依据版本；LocalStorage 写失败被吞掉，页面仍称“已暂存在本机”。现有跨页往返测试没有覆盖这些失败路径。

关闭标准：项目其他字段或其他标签页变化时保留本页输入，并明确处理基准冲突；暂存草稿绑定依据且恢复时校验；存储失败显示失败并保护内存输入，不显示已保存。未保存输入仍应阻止使用旧内容的付费预览/启动。补充同页自动保存、跨页冲突、刷新恢复与存储失败的行为回归。
