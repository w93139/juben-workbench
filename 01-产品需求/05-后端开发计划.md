## 下一阶段：跑通一部完整作品

按以下依赖顺序开发，不把它们当作已经交付的功能。

| 顺序 | 开发内容 | 完成标准 |
|---|---|---|
| P0 正式创作费用保护 | 独立于测评的任务估价、逐次用量/费用、累计预算、超时与不确定费用核算；分段拆解也纳入 | 请求前能看到预计范围和调用规模；未知计价或预算不足不开始；重复请求不重复预留；中断保留费用，不自动扩大预算 |
| P1 整本拆解验收修复 | 根据真实材料核查缺段、引用、角色/真相/轮次与待定项；保持成功摘要复用 | 必要材料实际处理，关键内容可核对；缺失/矛盾明确展示，不能以完成进度代替语义完整性 |
| P2 蓝图修订闭环 | 审查问题定位到相关字段；补关系、事件、知情、线索、主持/终局的修改能力；版本浏览与安全整理 | 不止能改概要；保存后关联检查和审查失效规则正确；版本上限有可操作恢复路径，整理不静默丢历史 |
| P3 长篇正文与审查 | 从固定蓝图按角色/模块/轮次生成；检查点、单模块失败恢复；完整覆盖与跨模块一致性审查 | 六类正文齐全且不是提纲；任务不因单次回复容量截断整本；每路审查能追溯覆盖范围，漏审不得通过 |
| P4 一部作品真实联调 | 拆解→方向→蓝图→正文→双独审→互审→复核→ZIP；以实际问题修复链路 | ZIP可打开，角色/主持材料对应最新通过版本；玩家文件不泄密，主持能执行；记录实际调用与待解决问题 |

P0工程实现可以自行推进；实际调用前的任务预算、供应商和数据发送范围沿用已有具体授权，缺失时再明确。本轮文档修复和服务启动不触发模型调用。阶段A若需要重新拆解，由用户在原项目主动点击；现版本尚未具备P0累计费用保护。

P4通过后进入[阶段B验收](06-当前验收清单.md#阶段b完整创作链路)，再安排真人试玩。不要把“两个模型都通过”当作真人体验通过。

## 后续：稳定保存与交付

1. **存储与任务保障**：项目备份/恢复、长期项目与版本存储、可恢复的任务执行队列；换设备仍可恢复正文及关联结果，取消/失败/重启语义清晰。
2. **统一模型网关**：启动已规划的LiteLLM Proxy、健康检查、进程恢复及适配器切换；模型路由不得绕过工作台预算和真实执行身份记录。
3. **成品与试玩**：角色分类下载、Word/PDF与印刷布局、主持物料、试玩反馈和修订；分别记录AI检查、人工检查与真人试玩。
4. **多人/部署**：账号、项目权限、限流配额、日志与监控、备份演练和部署。仅本机回环访问不能替代联网服务的鉴权，实际部署与权限变更按具体授权执行。

## 数据存放原则

| 内容 | 位置 |
|---|---|
| 代码、结构/迁移、非敏感模板、测试、需求 | 指定GitHub仓库 |
| 当前项目元数据/正文/蓝图/审查 | 浏览器LocalStorage/IndexedDB |
| 当前模型配置、目录登记、测评账本、任务/摘要缓存 | 本机被Git忽略的runtime-data；环境变量配置也只在服务端 |
| 后续长期项目/版本 | 受权限保护的数据库；具体选型在存储批次落实 |
| 原始材料及成品文件 | 本机原目录/输出目录；将来按授权接文件或对象存储 |
| 密钥 | 本机受限服务端配置或部署Secret，禁止Git/客户端持久存储 |

GitHub代码同步和创作数据备份分开验收；清理浏览器、缓存或本机目录前需有可验证的恢复方案。接入安全边界见[SECURITY](../SECURITY.md)。
