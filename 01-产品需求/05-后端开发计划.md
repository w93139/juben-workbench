# 后端开发计划

更新：2026-09-08。LiteLLM已列入计划；本文件是后续实施安排，当前未建立数据库、调用真实模型或部署服务。

## 1. 先完成的原型

| 批次 | 交付 | 状态 |
|---|---|---|
| A | 项目、页面导航、决定状态和检查边界 | 用户已验收 |
| B | 材料整理、模拟OCR、参考拆解、机制取舍、原创方向 | 已开发，待用户完成剩余交互验收 |
| C | 原创蓝图编辑、角色关系、时间线、知识与证据链、版本 | 用户反馈测试通过 |
| D | 分模块模拟生成、双模型模拟审查、分歧处理和复查 | 本轮交付，待用户测试 |
| E | 真人试玩记录、受众预览与模拟导出 | 待开发 |

前台采用五个主步骤：准备材料、确定创作方案、设计故事、生成与检查、试玩与导出。A—E是开发批次，与五步不一一对应；底层九个阶段及旧数据继续兼容。第二步集中方向与机制确认，第五步允许先导出未试玩包、再记录反馈并修订。

原型继续使用Mock验证完整操作流程。真实后端放在之后的F阶段，不因为建了GitHub仓库就算后端完成。

## 2. F阶段：真实后端

| 顺序 | 做什么 | 交付与验收 |
|---|---|---|
| F1：项目持久化 | 建立项目API、数据库、版本记录和必要的账号／权限；接上现有Service | 保存后重新登录或换设备能找回；其他账号不能读取；并发修改不静默覆盖；可备份和恢复 |
| F2：材料与任务 | 原文件存储、分片上传、分类提取、OCR／转写、后台任务 | 断线可继续，单项失败可重试；结果能定位页码或时间；停止网页不丢任务；未识别内容不冒充已识别 |
| F3：LiteLLM模型接入 | 独立部署固定版本的LiteLLM Proxy，后端通过适配器调用 | Kimi和DeepSeek各完成小样本调用；记录实际模型、用量和失败；密钥仅在服务端；预算、超时和重试上限有效 |
| F4：真实创作与交叉审查 | 将已验证Skill整理成有版本的执行配置，连接蓝图生成、正文生成、双审、互审与作者决定 | 两模型独立检查同一版本；分歧有证据；一侧失败可重试；修改后旧检查不自动通过；模拟与真实记录分开 |
| F5：真实导出与运行保障 | 成品文件、受众隔离、下载、备份恢复、监控和部署 | 玩家包不含主持谜底；输出文件可打开、路径可追踪；可恢复备份；真人试玩状态不被AI结果替代 |

F3之前确定供应商账号／区域、单任务和月度费用上限、运行位置。F5之前确定真实部署权限与访问范围。这些决定会影响费用和数据发送范围，实施时以用户具体授权为准。当前不购买服务、不发送剧本到模型。

## 3. 数据放在哪里

| 内容 | 位置与用途 |
|---|---|
| 代码、数据库结构／迁移、非敏感配置模板、演示数据、计划 | GitHub指定代码仓库，保留公开开发版本；不放真实用户数据 |
| 真实项目、角色、决定、版本、审查结果、试玩记录 | 后端数据库，建议PostgreSQL；可做项目级备份与恢复 |
| 原始PDF／图片／音视频、生成的角色本和导出包 | 文件／对象存储；数据库保存定位、来源、权限和版本 |
| 模型密钥、数据库密码 | 服务端配置或密钥管理，不提交GitHub |
| 浏览器已有项目 | F1增加备份导出、格式检查与导入迁移；原本机副本保留直到迁移验证成功 |

数据库结构可以进GitHub，真实数据库内容不默认进GitHub。浏览器目录授权引用不能跨设备迁移；换设备后需要重新选择输出目录。

## 4. LiteLLM的位置与边界

```text
前端页面 → 本项目Service/API → 任务执行器 → 模型适配器 → LiteLLM Proxy → 模型供应商
                              ↓
                        数据库与文件存储
```

本项目维护Skill、资料范围、角色与线索规则、任务版本、分歧处理和产物；LiteLLM统一连接模型，提供调用路由、重试和用量治理。[官方能力说明](https://docs.litellm.ai/)

采用独立网关，保留现有Next.js前端，不复制整个`litellm_internal_staging`源码。上线前选定并核验正式版本，确认所用功能的许可；Python任务执行器也可使用LiteLLM SDK，但不为此提前改写前端。接入适配器允许更换网关而不修改页面。

蓝图完成后与正文生成后各有审查入口。首轮两个模型分别检查；分歧再互审，作者决定采纳／暂定／不采纳。记录实际执行模型，不能在故障回退到同一个模型后仍称“双模型独立审查完成”。细节见[接入评估](04-多模型审查与LiteLLM评估.md)。

## 6. API接入安全验收

密钥只在服务端使用，本机用被忽略的`.env.local`，部署用平台Secret；公开仓库只保留空白模板。禁止客户端源码、构建产物、浏览器存储、URL和`NEXT_PUBLIC_`变量出现密钥。浏览器通过带身份和项目权限的后端调用，不直连模型网关。F3必须验证：越权拒绝、频率与并发上限、单任务及月度预算、最小权限与分环境密钥、撤销轮换、日志脱敏；不受信任的PR不能获得部署Secret。当前仅建立仓库扫描与接入要求，上述服务端能力尚未实施。发生泄露先撤销密钥，删除文件不能替代撤销；完整说明见根目录SECURITY.md。
