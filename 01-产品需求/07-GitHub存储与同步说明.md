# GitHub存储与同步

更新：2026-09-08。仓库：[w93139/juben-workbench](https://github.com/w93139/juben-workbench)，默认分支main。用户本轮已授权代码开源；发布前扫描与审查通过后切换公开，实际状态以GitHub为准。代码采用MIT，原创故事与研究摘录不自动取得MIT授权，见根目录LICENSE、NOTICE.md。

## 保存范围

仓库保存代码、数据类型、Mock演示快照、测试、产品需求和后端计划。Mock包含必要的原创故事摘要与机制研究摘录。原始参考资料、完整开本包、历史审查目录、外部Skill与agent-blueprint工程保持本机，不上传。

当前没有真实数据库；页面修改存于浏览器LocalStorage，输出目录引用存于IndexedDB。Git同步只上传仓库文件，不会读浏览器、备份创作状态或搬走本机文件。后续数据库结构进入代码仓库，实际用户数据通过后端数据库和文件存储备份。

## 同步时机

当前采用每轮开发完成后同步：完成修改 → 按Coding Workflow验证并审查 → 检查文件范围 → 提交版本 → 推送GitHub → 核对远程版本。此约定写入根AGENTS.md，后续在本项目开发时沿用。

没有安装每次保存即上传的后台监听。你自己编辑文件后，可以在Mac双击根目录`同步到GitHub.command`，或在终端运行：

```sh
python3 scripts/sync-github.py --message "说明这次改了什么"
```

脚本负责一次同步，不代替开发验证，也不会声称所有修改已经测试通过。先用`--check`可检查待同步文件与目标，检查模式不暂存、不提交、不推送。

脚本只允许指定仓库与main分支；接受该仓库由私有转公开后的状态，不会自行切换权限。检查工作区、暂存区和全部本地引用可达历史的范围、大小、常见凭证、敏感配置及私钥。独立运行`python3 scripts/check-repository.py`可只读扫描，不需登录，也不上传。GitHub Actions在push和PR后重复扫描，不能撤回已上传内容。自动检查不能识别所有个人资料，提交前仍应看文件清单和修改内容。

## 失败时

- 网络或登录失败：显示错误；本机文件和已有提交保留，恢复后再次运行。
- GitHub有人更新了代码：停止同步，保留双方修改，先处理远程差异；不会强制推送或覆盖。
- 发现超范围文件、常见凭证、二进制或超过10MiB的文件：停止并显示文件位置；不要通过强制添加绕过，应改用适合的文件存储。
- 没有修改：不会新增空提交；如有上次未推送的提交，会继续尝试同步。

成功后显示提交编号，并核对GitHub的main与本机HEAD相同。这证明代码版本同步，不证明网页创作数据或真实后端数据已经备份。

## 从GitHub恢复

重新克隆仓库，在`03-前端原型`运行`npm ci`和`npm run dev`。可以恢复代码与演示快照；浏览器里创建的个人项目不在该仓库中，需后续项目备份功能或真实后端恢复。

首次归档版本`bf298a9`已从GitHub克隆到独立临时目录，88个文件逐一哈希比较一致；原始参考目录、第三方工程、依赖和构建产物均未混入。同步工具8项隔离Git测试与独立只读复审通过，覆盖失败重试、远程领先、指定目标、额外标签及凭证历史保护。

## API安全边界

公开代码不包含API密钥。未来只在服务端被忽略的配置或部署Secret中保存，禁止客户端、浏览器存储和NEXT_PUBLIC_敏感变量。身份校验、项目权限、额度、限流、撤销轮换和日志脱敏属于真实接入前的必验项，当前未接API。防护与发现泄露后的处理见根目录SECURITY.md；不承诺绝对不会泄露。
