# 策划辅助工作台：当前验收清单

本清单替代旧的“整本正文生成 → 交叉审查 → 开本 ZIP → 真人试玩”验收流程。当前产品到**可编辑大纲、原创蓝图与策划交接包**结束。旧验收历史保留在 Git 与 TASK.md 中。

**不适用（产品范围外）**：实际正文改写、模型交叉审查执行、外部作者完成任务、成品可玩性和真人试玩。这些不是“尚未完成”的产品待办，不阻碍本产品验收。交接模板可以提供后续建议，但不要求用户执行；旧数据的 `not-run` 仅作历史或外部状态说明。

## 验收方法与边界

- 软件功能使用自造材料、假供应商及隔离浏览器验证；在当前提交上运行仓库必需检查，并复核已知反例。
- 真实模型产出的大纲与蓝图是否符合作者意图，属于作者对策划输出的内容判断；查看已有结果即可，不因本清单自动重跑付费任务。
- 每项记录“通过／失败／未测／不适用”，附当前证据。既有测试没有覆盖的行为，不用总测试数代替验证。
- 前段真实模型调用须先预览并取得既有流程要求的确认。页面查看、本地编辑和策划包构建不应调用模型。

## A. 材料与拆解

| 编号 | 检查行为 | 通过标准 |
|---|---|---|
| A1 | 新建、打开、刷新与恢复项目 | 项目与材料不丢失；存储失败明确报错，不静默当空项目 |
| A2 | 导入自造文本及读取失败材料 | 成功、排除、不支持、失败状态可辨认；不修改原件；必要材料不静默遗漏 |
| A3 | 拆解、查询进度与失败恢复 | 返回对应当前材料的结果；来源能定位到材料；刷新不自动重付费；失败保留材料与已完成记录 |
| A4 | 费用预览与执行边界 | 拆解、蓝图按当前输入预览并确认；新的正文/审查预览与启动在服务端被拒；本地交接导出零模型调用 |

## B. 作者大纲、方向与蓝图

| 编号 | 检查行为 | 通过标准 |
|---|---|---|
| B1 | 编辑大纲和方向、保存、重新打开 | 已保存作者版本用于方向选择、蓝图请求与交接包；模型原版可区分 |
| B2 | 未保存编辑、跨页、刷新、同页保存其他字段、跨标签修改 | 输入不会静默丢失；暂存失败明确提示；版本冲突保留草稿；未保存编辑不能被旧内容的付费流程绕过 |
| B3 | 同材料重新拆解、换材料再拆解 | 作者修订绑定实际分析结果版本；旧作者内容不会自动覆盖新分析，历史内容保留且可辨认 |
| B4 | 蓝图编辑、保存、当前性与关联校验 | 九类结构可编辑；缺失引用明确定位；材料、方向或设计依据改变后旧蓝图不能冒充当前成果 |

## C. 策划交接包

| 编号 | 检查行为 | 通过标准 |
|---|---|---|
| C1 | 草稿/正式包与来源状态 | 结构或来源缺口明确列出；来源定位不冒充逐条内容核对；包是策划方案，不宣称完成正文 |
| C2 | 导出内容与格式 | Markdown/JSON 可打开且一致，包含当前大纲/方向、蓝图、写作任务及可选核验建议；原始材料正文、配置、账本不自动入包 |
| C3 | 任务分发范围 | 只有明确公共的线索进入公共卡；限定、否定、条件矛盾或无法确定的描述进入主持待确认；玩家开场任务不提前收入未来轮次知识 |
| C4 | 导出期间项目发生变更 | 下载前完成保存修订核对和原子版本检查；冲突时两个文件均不下载，不写成功标记 |
| C5 | 支持的规模与旧数据兼容 | 支持既有合法蓝图的规模；旧正文、报告、阶段成果、备份和账本可读，旧通过资格不能被策划包继承 |

## D. 产品范围与交付记录

| 编号 | 检查行为 | 通过标准 |
|---|---|---|
| D1 | 导航、主要按钮、状态和说明 | 四步止于策划交接；没有新的正文改写/审查启动入口；真人试玩不显示为产品完成门槛 |
| D2 | 工程验证与同步 | verify-app.py 在受检代码上通过；独立审查关闭阻断/重要问题；只同步已授权代码、测试和文档 |
| D3 | 当前版本验收报告 | 写明受检提交、通过/失败项与实测反例；产品范围外事项记录“不适用”，不列入未完成 |

## 使用与反馈

本机地址为 http://127.0.0.1:3107；原浏览器和原地址的创作数据与 GitHub 代码版本分别管理。隔离检查使用独立构建和自造数据，不代表本机运行服务已自动更新。

反馈采用“编号 + 结果 + 现象/错误原文”。例如：B2 失败，保存创作要求后未保存大纲被清空；C4 通过，构包期间修改项目后下载数为 0。不要贴密钥、整本原文或账本内容。最终软件验收只依据本清单范围。
