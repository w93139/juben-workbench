# 当前阶段验收清单

更新：2026-09-10。**现在需要阶段性验收，范围先定为“材料读取与完整原剧本拆解”**。开发检查验证程序行为，用户验收确认真实材料与创作需求；完整成品另列阶段B，真人试玩再单独进行。

## 地址与准备

- 地址：**http://127.0.0.1:3107**，在运行本项目的这台Mac上打开。
- 使用之前保存项目的同一个浏览器和同一地址。`localhost`、其他端口或隔离浏览器不是相同存储位置；新浏览器无项目不等于原项目丢失。
- 服务未运行时，在`03-前端原型`用Node.js 24执行`npm ci`、`npm run build -- --webpack`、`npm run start -- --port 3107`。不要在已有任务运行中重启。
- 刷新原项目，核对顶部四步与输出目录。2026-09-09最近记录为模型小样9/9完成；无需为了本轮验收重新测评或重新提交Key。当前连接状态以页面为准。
- 查看已有结果、切换页面和刷新不触发模型生成。重新点击“拆解大纲”“生成蓝图”“开始交叉验证”会发起真实模型调用；长剧本拆解可能多次调用。测评10元估算上限不覆盖正式创作，当前没有正式创作累计费用账本。

## 阶段A：材料与整本拆解

先检查已有结果。只有缺少当前材料的有效拆解或确需重试时，才主动重新拆解。

| 编号 | 怎么验收 | 通过标准 |
|---|---|---|
| A1 原项目与导航 | 刷新并切换四步，再回到材料 | 项目可找到；四步固定为准备材料、拆解与方向、创作蓝图、交叉验证与导出；主要按钮可见，既有资料不丢 |
| A2 输出位置 | 选择准备保存成果的目录，刷新；再打开选择窗口并取消 | 显示所选目录并保留；取消不改变位置；只登记目录，不自动新建子文件夹或写出ZIP |
| A3 材料完整性 | 展开“查看文件明细”，对照原文件夹；抽查角色本、主持本、线索等必要文件 | 份数/相对路径合理，每份必要材料有有效正文；空正文、读取失败或不支持项明确列为待处理；只有本人明确不需要的材料才排除 |
| A4 整本拆解 | 材料就绪后点“拆解大纲”；大输入观察分段与汇总进度 | 不再因旧600 KB入口限制要求删必要原文；长输入显示批次，所有批次成功后才有结果；失败显示所在步骤，不冒充完成 |
| A5 内容核对 | 对照原本核查主线真相、关键因果、主要角色关系、关键线索与轮次 | 关键内容没有漏掉或张冠李戴；事实、推断、原创建议、待确定项可区分。至少抽查5条来源摘录，尽量覆盖不同文件及靠前/中间/靠后内容，摘录与定位对应正文 |
| A6 原创方向 | 阅读全部方向建议 | 有2—5个可区分的方向，有概要与风险；重建人物、动机、因果和线索，不只是换名字或背景；能选出愿意继续发展的方向 |
| A7 刷新恢复 | 处理过程中正常刷新一次，完成后再刷新一次 | 继续查看同一任务进度或已完成结果，没有因刷新自动重新拆解；失败后能读懂原因并继续操作。费用/请求幂等由开发测试验证，页面观察不能单独证明平台未重复计费 |

通过规则：A1—A7适用项逐项记录结果；未测到的分段或失败场景标“未测”，不能记通过。缺少必要材料、主线真相错误、虚构引用、失败却显示完成、刷新丢结果，均为阻断。方向风格不满意应列为创作反馈，不靠程序测试代替判断。

证据数量不足时：若拆解只提供少于5条引用，记录“待补证据”，对现有引用逐条核查；不要为凑足数量反复付费重试。

失败恢复补充：服务端完成结果/通过快照保留7天；服务退出或租约超时后，进行中的任务会标记中断，不自动重新调用。手动重试同材料时可复用7天内成功摘要。无需为验收故意中断付费任务；这些边界由开发侧隔离测试覆盖。

## 阶段B：完整创作链路

本阶段用于下一批真实联调之后的验收，**不是当前已通过项目，也不要求现在一次测完**。优先补正式创作费用保护、复杂蓝图修订和长篇生成/审查能力，详见[下一阶段计划](05-后端开发计划.md)。

| 编号 | 验收内容 | 通过标准 |
|---|---|---|
| B1 蓝图 | 选择方向生成蓝图，检查并修改关键设计 | 角色有目标/秘密/选择与贡献；时间、知情、证据和轮次一致；复杂问题有可操作的修改入口，保存后旧审查失效 |
| B2 正文 | 开始交叉验证中的全文生成 | 角色本、私人信息、阶段更新、公共线索、主持手册、终局六类齐全；正文可读可执行，不是摘要或占位；所有角色与轮次覆盖明确 |
| B3 审查 | 查看真实环节和最终报告 | 主模型设计门、两路独审、互审、主模型复核对应同一版本；问题有可核对证据；任何未解决阻断不能导出，修改后重审 |
| B4 导出 | 全链通过后“导出完整档案”，解压ZIP并抽查 | 实际写入所选目录；包含蓝图JSON、Markdown正文和审查报告；玩家按角色与主持分区，玩家材料无主持谜底或其他角色秘密；同名文件不覆盖 |
| B5 状态与费用 | 核对版本、真实调用和试玩状态 | 产物对应当前通过快照；真实创作费用记录可追踪；仍明确“尚未真人试玩”，不把AI通过当作可玩性结论 |

当前限制：非拆解步骤仍有单次600000字节上限，六类正文仍一次生成；蓝图复杂结构目前仅查看，最多20份历史且尚无整理入口。遇到这些限制记录问题，保留资料，不通过删除必要内容或反复付费重试凑通过。ZIP目前不含Word/PDF转换结果。

## 反馈格式

直接按“编号＋结果＋现象”反馈即可，例如：

> A1通过；A3有2份扫描线索无正文；A5主线正确，但某角色知情时间写错；A6选择第二个方向；A7未测。

失败时补充所在步骤、页面错误原文和大致材料规模。可提供必要截图，不发送API Key或整本原文到公开Issue。当前A/B均等待实际验收反馈；历史开发测试和旧作品结论不自动填入本表。
